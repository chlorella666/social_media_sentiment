## 一、问题定义（2026-08-17 修正，替代旧 game/consumer 口径）

**其他品类提准 ≠ 游戏/消费品两个评测域**，而是让三大模块的分析质量
（维度合理性 + 情感准确率）可验证、可提升：

| 模块（用户侧） | 模板 id | 现有评测覆盖 | 状态 |
|---|---|---|---|
| 数字产品 | content | game 领域 golden | 有覆盖，game 78.1% 是短板 |
| 有形实物 | physical | consumer + digital3c golden | 有覆盖，3C 已全量 LLM |
| 服务内容 | service | 无独立覆盖 | 零裁判样本，本轮补齐 |

模块分类的产品目的是**帮助用户选 LLM 分析维度**（不是评测域标签）：品牌多样，
单领域覆盖不了；模块多选让维度组合贴合品牌对象（零售商 = 有形实物 + 服务内容），
报告维度更合理、归因更清晰。

## 二、已确认决策（2026-08-17）

1. **纯模块生成维度**：所有品牌一律由模块模板生成维度，不做品牌→领域映射；
2. **③ 关键词页只预填品牌名** + 风控提示；关键词优化开关集中到本页；
   评测中心「关键词策略配置」为关键词优化进阶通道（深链 `?tab=strategy`）；
3. **服务内容纳入数据侧**，复用历史报告（零售/餐饮品牌）；
4. **用户侧命名**：数字产品 / 有形实物 / 服务内容；模板 id content/physical/service 不变。

## 三、审核修订（2026-08-17，专业审核后吸收）

- P0-1 模板维度关键词全部为空 → 已从 game/consumer/digital3c 同源维度回填
  （service 新起草），模板 version 0.1→1.0、status draft→production；
- P0-2 关键词只预填品牌名导致采集量骤降 → ③ 页引导 + 评测中心策略通道 +
  优化开关默认开（用户否决了扩展词 chips 方案）；
- P0-3 出口判定重写（模块卷无历史基线，见 §七）；
- P1-4 双轨评测口径：领域卷只做整条情感回归 + 历史可比，模块卷承担维度级裁判；
- P1-5 组合维度强制 ≤10（超出必须取消勾选）；去重规则：价格/品牌/渠道售后/
  功能稳定四组合并，命名 = 价格价值 / 品牌形象 / 渠道服务与售后 / 功能与稳定性；
- P1-6 hold-out 45~60 条（分模块三卷）、单品牌 ≤40%/卷、超抽 20~25%；
- P1-7 服务卷双口径出口（整条 n + 维度 n）；
- P1-8 模板 draft 状态进生产 → 模块卷即"证据定稿"流程。
