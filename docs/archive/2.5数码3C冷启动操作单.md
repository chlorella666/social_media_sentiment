# 数码 3C 冷启动真实采集操作单（2.5，2026-08-15）

> 目标：采集 100~200 条数码 3C 真实评论 → 独立标注 → 定版 → 正式裁判与独立基线。
> 前置：确认表已应用，`data/domain_schemas/digital3c.json` 已落库（UI 领域下拉可见「数码3C」）。

## 一、采集（应用内任务）

1. 启动应用，向导 ① 输入对象：品牌选 大疆 / 影石 / 联想 / 苹果 / 华为（可多个任务），
   领域选「数码3C」；② 维度默认全选（7 维）；③ 关键词自动生成（品牌 × 维度词）；④ 渠道与时间。
2. 渠道建议与上限（沿用渠道矩阵）：
   - **B站（零登录，最稳）**：默认 20/关键词；
   - **WebSearch**：默认 13/关键词（风控注意：每日关键词总量上限 24，建议分 2~3 个任务跑）；
   - **微博**：需 Cookie（侧边栏保存 DPAPI），默认 20/关键词；
   - 小红书：反爬严，可不用于首批。
3. 建议：5 个品牌 × 每品牌 1~2 个任务，混渠道，目标去重后 100~200 条。

## 二、采样生成独立标注表

```powershell
python tests/coldstart_annotation.py --from-report data/reports/<任务目录> `
    --domain digital3c `
    --n 120 --out data/datasets/coldstart_digital3c_worksheet.xlsx
```

标注表字段：原文/平台/品牌/关键词/文本类型 + 7 个维度列（留空）+ 情感/强度/相关/语言现象
（全部留空 = **独立标注**，不看程序结果，避免被诱导）。
> 维度列按已落库 schema 动态生成（7 维）；仅当 schema 尚未落库时才需补
> `--dims-json <提案.json>`（此时为提案候选维度）。

## 三、标注与复核

1. 双 AI 标注（workbuddy 主标 + trae 副标，复用 2.3 流程）或 1 人标注 + 20% 双人复核；
2. 判例沿用《抽样与标注规范》§五（转折句逐维拆解、只提无褒贬留空、relevant=no 维度清空）；
3. 质量线：整条情感一致率 ≥80% 目标；**维度级 A 档参考，不设硬门槛**（2.4 口径）。

## 四、定版与基线冻结

```powershell
python tests/coldstart_annotation.py --finalize --sheet <标注表.xlsx> `
    --out data/datasets/coldstart_digital3c_golden.csv --domain digital3c
python tests/benchmark_golden.py --golden data/datasets/coldstart_digital3c_golden.csv `
    --mode-key domain_digital3c_lexicon --report-out data/datasets/digital3c_report.json
```

词典基线达标后重冻结 `tests/fixtures/baseline_domain_digital3c_lexicon.json`；
混合基线（LLM v3.0 维度情感）由用户侧 `--mode-key domain_digital3c_hybrid --llm` 两轮确认。
正式裁判 n 建议 ≥100（relevant=yes），维度样本 n<30 的维度按 A 档参考。

## 五、转正

裁判+基线达标 → 把 `data/domain_schemas/digital3c.json` 复制到 `app/domains/digital3c.json`
（入库受版本管理）→ schema 契约测试纳入 → UI 领域文案确认 → 标记「正式领域」。

## 六、注意

- WebSearch 每日关键词上限 24，超限任务会失败（可次日补跑）；
- 采样去重后不足目标量属正常，多品牌/多渠道叠加；
- 骨架基线（公开语料 83.3%，n=60）仅用于链路验证，正式基线以本操作单产出为准。
