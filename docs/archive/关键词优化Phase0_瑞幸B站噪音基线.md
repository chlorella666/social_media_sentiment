## 一、结论先行

**瑞幸 × B站 的报告质量瓶颈不是"官方/广告噪音"，也不是"关键词少"，
而是采集层同一视频/评论被重复返回**——修复去重后，消费者声音占比可从
约 33%（唯一口径约 53%）进一步提升，关键词优化（扩词）在本渠道暂不构成
优先投入。

## 三、重复来源诊断（关键发现）

- 两轮共 **42 个重复组、141 条重复文本，全部为"单 URL"**——即**同一视频/评论
  在单轮搜索结果中被重复返回**（搜索 API 分页/推荐位重复），cleaner 按
  "相同正文"判重后丢弃；
- 不是"不同视频同标题"、不是评论级跨视频重复；
- 结论：**采集层 URL/视频去重未完全生效**（bilibili collect 已有 seen_ids，
  但同一视频可能以不同 bvid/URL 形态出现，或分页重复未拦住）；
- 修复方向（轨 A·A4）：collect 层按视频 ID + 规范化 URL 去重强化、
  cleaner 判重保留首个完整文本；改动后全量回归。

## 七、A4 修复验证（2026-08-18 补充）

- **根因**：B站视频 content 常为空/短简介/等于标题，cleaner 的正文去重键
  （content[:50]）把大量唯一视频误判为「重复（相同正文）」；且"重复丢弃"
  计入补采触发率，形成"重复→补采→再重复"回路（44/50 条重复丢弃）。
- **修复**：① 正文去重键仅对"长度 ≥20 且 ≠ 标题"的真实正文生效；
  ② 补采触发只看"质量丢弃"（排除重复）；③ collect 按 bvid+URL 双键去重。
- **复测（修复后真实采集一轮）**：
  - 保留 18 条（修复前 10 条）；丢弃 1 条（修复前 50 条，其中重复 44）；
  - 丢弃原因：仅"文本过短"1 条；
  - **消费者声音占比 E/N = 94.7%**（修复前 14%~33%）；
  - 分档仍"不足"：E=18 ≥ 够用线但 negative n=3 <10（词典模式 + B站标题
    多为中性/正向语体）——捕获问题已解决，分档口径按渠道校准见待办。
- 判例表复核结论：32 条中 27 真实消费者、3 官方/媒体口径、2 不相关；
  保留集校准通过（ad_rules 已覆盖唯一一条"官方回应"），无需改 ad_rules。

## 八、分档口径按渠道校准（2026-08-18）

- 问题：修复后瑞幸×B站 E=18~20、占比 94~100%，但分档固定要求 neg≥10
  → 实测 neg=3 被判"不足"，捕获问题已解决却被误报。
- 修复：`voice_tier` 正/负最小条数改为「比率 × E」——默认 0.1，
  `VOICE_TIER_CFG` 中 bilibili/demo 为 0.05（标题语体显式负面占比低）；
  summary.consumer_voice 记录 tier_channel 与 tier_ratios 便于审计。
- 复测：瑞幸×B站 E=20、pos=1、neg=3 → tier「充足」（校准前"不足"）。
- 待办：随数据积累，按渠道统计实际正/负率进一步校准比率表。

## 九、轨 B（扩词）边际增益评估与结项（2026-08-18）

- 实测（瑞幸×B站多关键词：瑞幸 / 瑞幸 联名 / 瑞幸 新品，各 limit 20）：
  - 瑞幸 19 条（base）→ +联名 9 条（+47%）→ +新品 5 条（+26%）；
    合计 33 条唯一内容（+74%，0 重叠）；
  - 有效率/消费者声音：单关键词 E/N≈100% 已饱和；三词 E=32/36=88.9%；
  - 边际递减明显（+47% → +26%），5 词上限下后 3 词继续递减。
- **结论**：扩词的真实价值 = **信息面扩展（子话题覆盖）**，不是提准
  （有效率已饱和）；B站公开 API 成本低但采集配额/耗时按词数线性增。
- **判定：轨 B 在 B站不作为提准优先项推进，予以结项**；扩词保留为
  "子话题覆盖"可选能力（渠道策略按需配置、用户主动开启）；
  其他渠道（微博/小红书）Phase 1~3 候选词验证按需推进，沿用三指标验收。
