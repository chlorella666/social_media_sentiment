# 黄金集抽样与标注规范

> 版本：v1.0（2026-08-07 定版） | 日期：2026-08-07
> 状态：187 条定版（AI 一致性标注回归集 + 40 条人工抽检校准，黄金集 v1.1）
> 关联：[项目方案.md](../项目方案.md)（评测基准）、[渠道验收矩阵.md](../渠道验收矩阵.md)（数据来源）

## 一、目的与定位

建立**黄金集**（v1 为 AI 一致性标注回归集，人工抽检校准中），作为情感判定、维度标注、
清洗相关性的统一裁判，解决当前
"公开语料 + LLM 伪标签"评测的自我印证偏差（详见项目方案"本地轻量模型评测结论"）。
同时为未来"维度级情感（aspect-based）"功能预存验证数据，避免后续返工。

规模目标：**首批 200 条跑通流程，目标 500 条**。

用途：

1. 每次词典/LLM 提示词/清洗规则改动后跑分对比（改前 vs 改后）
2. 按渠道、领域、情感类别、语言现象细分质量，发现偏科
3. 作为关键词策略、维度 schema、置信度阈值调整的依据

## 二、样本来源

- **必须来自真实采集数据**：微博 / B站 / 小红书 / WebSearch（含 websearch_zhihu、
  websearch_tieba、websearch_taptap 子渠道）四个渠道，游戏 / 消费品两个领域
- 现有可用数据：`data/reports/验收试跑v4_*/`（情感编码明细，含正文与评论）；
  也可新采集补充
- 文本类型：帖子正文、评论、楼中楼（"是否回复=是"的样本）都要覆盖
- **排除项**：已被清洗丢弃的样板/官网/过短/重复文本不进入主集；丢弃样本
  单独构成**清洗验证集**（见 §八），用于验证清洗规则是否误杀

## 三、抽样设计

### 总量与分层

| 维度 | 分层 | 首批比例 | 首批条数 | 目标条数 |
|------|------|----------|----------|----------|
| 渠道 | 微博 | 25% | 50 | 125 |
| 渠道 | B站 | 25% | 50 | 125 |
| 渠道 | 小红书 | 25% | 50 | 125 |
| 渠道 | WebSearch（含子渠道） | 25% | 50 | 125 |
| 领域 | 游戏 / 消费品 | 各 50% | 各 100 | 各 250 |
| 文本类型 | 帖子正文 | 40% | 80 | 200 |
| 文本类型 | 评论 | 50% | 100 | 250 |
| 文本类型 | 楼中楼 | 10% | 20 | 50 |

### 边界样本定向配额

按比例抽满后，定向补齐以下样本（不达标需说明原因）：

| 语言现象 | 目标占比 | 说明 |
|----------|----------|------|
| 反讽/阴阳怪气 | ≥10% | "这波操作太棒了"类 |
| 网络黑话 | ≥10% | 绝绝子/yyds/塌房/割韭菜 等 |
| 长文本（>100 字） | ≥15% | 考验长文情感聚合 |
| 多维度文本 | ≥15% | 一条文本同时涉及多个维度，是维度级情感标注的主要样本基础 |
| 官方/广告内容 | ≥10% | 官方公告、宣发、带货 |
| 中英混杂/繁体/emoji 主导 | ≥5% | 口语与平台语体多样性 |

### 抽样规则

1. 按"渠道 × 领域"分层随机抽样，用固定随机种子保证可复现
2. 同一帖子最多取 3 条评论，避免单帖倾斜
3. 先按项目既有四重去重逻辑去重，再去抽样
4. 每条样本记录来源信息：平台、链接、作者、点赞、发布时间、采集批次，
   保证可回溯、可复现

## 四、标注字段

| 字段 | 取值 | 必填 | 说明 |
|------|------|------|------|
| text_id | 字符串 | 是 | 与采集批次唯一对应 |
| sentiment | positive / negative / neutral / mixed | 是 | 整条情感（综合结论）；mixed 仅用于无法按维度拆解时（见 §五） |
| intensity | 1~5 整数 | 是 | 整条情感强度（neutral 标 1） |
| dimension_sentiments | 每维度一列：positive / negative / 空 | 是 | 每个"明确带情感"的维度各标一个情感；无明确褒贬留空（整条情感保留 neutral，见 §五） |
| language_flags | 多选 | 否 | 反讽 / 黑话 / 方言 / 官方 / 广告 / emoji 主导 / 无观点；没现象不填（无"无"选项） |
| relevant | yes / no | 是 | 是否与品牌/主题相关（验证清洗相关性） |
| remark | 文本 | 否 | 歧义与判定理由 |
| annotator | 文本 | 是 | 标注者标识 |
| annotated_at | 日期 | 是 | 标注时间 |

**标注表形态**：宽表——每条文本一行、每个维度一列（维度列按所属领域 schema 动态
生成；当前游戏/消费品各 7 列）；
维度列下拉仅含 positive / negative（Excel 校验）；定稿 CSV 将维度情感压缩为
JSON 字段 `dimension_sentiments`（见 §八）。

### 维度枚举（与领域 schema 一致）

- 游戏（game）：角色 / 剧情 / 氪金 / 美术 / 玩法 / 运营 / Bug
- 消费品（consumer）：质量 / 价格 / 体验 / 品牌 / 渠道 / 安全 / 竞品
- 不适用时整条情感标 neutral，维度列全部留空；命中 schema 外维度时在
  remark 写明

## 五、标注规则（判例）

1. **整条情感 + 维度拆解并行**：先读全文定整条情感（综合结论），再对每个
   "明确带情感"的维度单独标情感；**维度值只填 positive / negative，无明确
   褒贬留空；整条情感保留 neutral**（v0.3 试标对齐）
2. **转折句逐维拆解**："画面好但价格劝退"→ 美术 positive、价格 negative，
   整条 negative；"贵是贵但值"→ 价格 negative、体验 positive，整条 positive
3. **反讽/阴阳怪气**：只用于"表面正向/中性、实际负向"的文本
   （"这波操作太棒了"→ 负面）；意图无法判断 → 整条 neutral + 反讽标记；
   **直接批评不算反讽**（v0.3 试标对齐）
4. **疑问句**：有明确倾向按倾向（"这价格谁买得起？"→ 负面）；纯疑问 → neutral
5. **无观点/纯转发/官方公告** → 整条 neutral，维度列全部留空；
   语言现象只标"官方"，**不再叠标"无观点"**（v0.3 试标对齐）
6. **mixed 严格限制**：方案 B 下正负观点通常已被维度拆解吸收，mixed 仅保留给
   "无法归到具体维度、又定不了主倾向"的文本；占比应 <2%，>5% 需复核规则
7. **黑话与 emoji**：黑话指圈内词/网络词（糖豆、骨科、工业糖精等），
   标了就在备注写明含义；emoji 情绪明确（😡😍）可作情感依据，
   承载情感时标"emoji 主导"（v0.3 试标对齐）
8. **不相关内容**（跑题/引流/广告）→ relevant=no，情感标 neutral；
   该类样本单独统计，不计入主情感评分
9. **过短（<5 字）且无情感** → 不纳入主集
10. **独立标注优先**：正式标注轮不看程序结果，避免被词典/LLM 判定诱导；
    程序结果仅用于"审核修正"模式（见 §六）
11. **维度情感口径**：卡面/立绘/文案按 schema 词表标（美术反馈 + 剧情评价
    可同时标）；论证长文提到玩法/机制/战斗 → 标玩法体验；**纯玩家互动
    （鼓励、社区氛围等）→ 标"运营与社区"，情感按内容标**；只提到没褒贬
    → 留空；拿不准用 remark 说明（v0.3 试标对齐）
12. **强度锚点**：1=无/轻微、3=明显、5=强烈；两人相差 1 分属正常，
    不必强改（v0.3 试标对齐）
13. **语言现象**：没现象就不填（不再有"无"选项）；官方公告不叠标"无观点"

## 六、标注流程

1. **生成标注工作表**：抽样脚本输出宽表 CSV/Excel，含原文与来源信息，
   **不含程序判定结果**（独立标注轮）
2. **试标对齐（首批 20 条）**：标注者共同标完并讨论，重点对齐
   维度级情感口径（哪些维度算"带情感"）
3. **正式标注**：**主标注人一人标注全部**，每批 50 条
4. **核对**：随机抽 20% 由第二人独立标注；**mixed、反讽、relevant=no
   高歧义样本 100% 复核**
5. **一致性计算**：在双人核对子集上逐批计算整条情感一致率与 Cohen's kappa，
   另算维度级情感一致率
6. **分歧处理**：分歧样本 → 两人讨论或第三人仲裁定稿 → 单独归档为"争议集"
7. **定稿发布**：生成 `golden_set_v1.csv` 与版本说明

## 七、质量控制

- **核对子集达标线**：整条情感一致率 ≥0.8，Cohen's kappa ≥0.6；
  维度级情感一致率 ≥0.75（口径更细，标准略低）；不达标则复盘标注规则
  并重标分歧批
- **试标基线（2026-08-07，20 条）**：整条情感一致率 100%、强度 75%、
  维度级 75%、语言现象 45%、是否相关 100%。语言现象一致率仅作参考，
  不作为硬性达标线；正式标注按 v0.3 口径后维度级应高于 75%
- **高歧义样本全量复核**：mixed / 反讽 / relevant=no 由第二人全部复看
- 每批抽检 10% 复核
- 格式校验：枚举值、必填字段、intensity 范围、维度列非空约束
- 分批标注、避免疲劳；记录每批一致率趋势

## 十二、边界样本专项集标注说明（标注人版，2026-08-13 增补）

### 3. 边界集特有规则（重点）

1. **「子集」列已预填，但它不是标注结果**：它是抽样时的分组标签（反讽/黑话/方言/
   长文本/emoji主导/低置信）。这条文本**真命中**对应语言现象，才填到「语言现象」列；
   不命中就留空，不要照抄子集名。
2. **低置信子集**是词典判定拿不准的文本，请重点核对，拿不准在备注写理由。
3. **独立标注**：不看程序或词典判定结果，避免被诱导（工作表情感/强度列已留空，
   这正是为了独立标注）。
4. **长文本（>100 字）** 先通读全文定主倾向，再按维度拆解，不要被开头或结尾局部带偏。
5. **方言** 按真实语义判断情感，不因看不懂方言就标 neutral；拿不准在备注写明。

  副标填 `data/datasets/annotation_edge_v1_trae.xlsx`（或同名 .csv）；
  填写时注明标注人标识与日期。
- 达标线：整条情感一致率 ≥0.8、Cohen's kappa ≥0.6、维度级一致率 ≥0.75；

## 十三、现象样本的品牌/领域/维度标注规则（2026-08-14 增补）

> 背景：边界集的反讽/方言/emoji 子集用**现象信号词**（唔该/好正/巴适/无语/太尴尬等）
> 采样，天然无品牌锚；2026-08-13 元数据修复曾把命中现象词的行品牌一刀切置空
> （包括文本里真实提到品牌的）。对 2.3 整条情感裁判无影响，但会污染 2.4 维度裁判。
> 以下规则由 2.4 前置复核（104 条）定版，工具实现见 `tests/edge_dimension_review.py`。

1. **品牌列 ≠ 现象关键词**：现象样本的「品牌/主题」列以**文本中真实出现的品牌/店铺**
   为准（如"唔该茶铺""鲜知味""爆煲先生""顺丰"），不能用采样关键词顶替；确实无品牌
   则留空并标记「现象样本」。
2. **无品牌行的维度情感分级**：
   - 品牌锚定：文本含真实品牌 → 品牌召回后维度情感进入**品牌锚定主口径**；
   - 类别级参考：确无品牌但内容是真实体验（如"佛山探店""演出流水账"）→ 维度情感保留，
     标记「类别级参考」，评测单列，不混入品牌主口径；
   - 无明确对象或跑题 → 维度留空。
3. **相关与维度联动**：`relevant=no`（跑题/广告/无观点）维度必须清空；`relevant=yes`
   且无品牌的行必须满足"品牌召回 / 类别级参考 / 维度清空"三者其一，否则定版拦截。
4. **领域按内容判定，不按采样词**：现象样本不默认 consumer；游戏内容标 game、
   真实消费品标 consumer、社会事件等标 other。领域变更时旧领域维度词汇不迁移，
   该行维度清空并退出维度裁判（整条情感裁判保留）。
5. **维度裁判口径**：品牌锚定行为主口径（品牌级维度统计/基线），类别级参考单列，
   n 与口径随评测报告标注；样本不足的维度不设硬门槛（A 档人工验收收口）。

## 十四、品牌口碑场景的"跟本品牌"口径（2026-08-15 增补）

> 背景：数码3C 冷启动裁判（2.5 首案例）采用"整条情感跟锚定品牌"口径——工作表
> 「品牌/主题」列是锚定品牌，整条情感按本品牌定，而非文本自身情绪。例如
> brand=影石、文本夸大疆 → 对本品牌是负面，整条 negative。
>
> 与默认口径的关系：主集/边界集沿用"文本自身情感"口径；"跟本品牌"仅用于
> 品牌口碑场景（新品口碑评估类新领域），且必须在标注说明页显式声明。
> 当前 LLM 只收文本、不收锚定品牌，该口径差异会造成"模型判文本自身情感 vs
> 裁判按品牌定"的系统性偏差——subject 传入 LLM 的适配评估见 2.6 数据侧。

1. 适用前提：分析对象是具体品牌（非泛主题/现象样本），且用途是品牌口碑监测；
2. 标注说明页必须写明"整条情感跟锚定品牌"，否则默认"文本自身情感"；
3. 竞品对比维度按文本内容标（夸竞品=竞品对比 positive，同时对本品牌整条 negative）；
4. 与 §五 判例的关系：§五 仍为默认判例；本口径只覆盖"锚定品牌 vs 竞品"的整条
   情感方向，维度标注规则不变。

## 十五、hold-out 留出集口径（2026-08-15 增补，2.6 验证纪律 V1）

> 目的：防"同集迭代拟合放大"——迭代集的提升可能是刷题刷出来的，必须用一份
> 冻结后只读的新样本卷子（hold-out）证明"真提升"。适用对象：**提准类改动**
> （提示词/词典/路由等影响准确率的实验）；降费类沿用主集+边界集双跑即可。

1. **来源与切分**：新采集（3C 后续补任务、2.6 生产难例回流）先切 30~50 条。
   工具：`tests/coldstart_annotation.py --holdout-split --from-report <目录>
   --domain <id> --n 30~50 --out-dir <目录>`。
2. **同分布约束**：按 (平台, 品牌) 配额分层 + 时间窗三分桶覆盖；分层占比偏差
   >10pp 或时间桶缺失（池内该桶 ≥10 条）即判定切分不合格（防止把分布差异
   误当模型提升）。seed 固定可复现。
3. **标注与定版**：复用 coldstart 工具链（标注表 → 双 AI/人工 → 定版
   `holdout_<domain>.csv`）；hold-out 与迭代集互不串用。
4. **冻结后只读**：定版后 `--freeze-holdout` 写指纹+冻结标记；hold-out 错误
   一律不进失败模式分析、不据此改规则；每里程碑重切新卷，旧卷作废。
5. **验收次数上限**：每份 hold-out ≤2 次验收（`benchmark --golden
   holdout_*.csv` 自动计数）；**首跑 = 建立基线（计 1 次使用），不构成提升判定**；
   第 2 次才是"同向提升"判定；达到上限后必须重切。
6. **判定标准**：迭代集提升 && hold-out 同向提升，且 hold-out 点提升超出其
   95% CI（30~50 条 CI ≈ ±14~18pp）；不满足显著性门槛则判定"待更多样本"。
7. **入库**：hold-out golden 去 URL 版写入 tests/fixtures（与 edge_set 同惯例）；
   主集/边界集暂无可切的新数据时，提准判定先用 V3 严格判定 + 双跑 + 跨领域
   防退化，hold-out 数据靠生产难例回流滚动补齐后复核。
