## 一、目的与原则

2.6 重心是**提准**。每次提示词/词典/路由改动后，都需要你侧执行 LLM 跑分验证。
原则（M1 验证纪律）：

1. **每轮跑 2 次取均值**（LLM 单轮 ±2pp 噪声实证：3C 两轮 70.1/72.2）；
2. 结论看 `status`：**噪声内（±X pp）/ 改善 / 回退**，不看单轮点估计；
3. hold-out 卷子 **首跑 = 建立基线**（计 1 次使用），第 2 次才构成"同向提升"判定；
4. 费用：每轮约 ¥0.1~0.2、2~6 分钟，20 轮约 ¥10——不是约束，放开跑。

## 二、准备

- 在项目根目录打开命令行（Windows：`D:\app\codex\social_media_sentence`）；
- LLM Key：应用侧边栏保存过（Windows DPAPI）即可被脚本读取；或临时设置
  `OPENAI_API_KEY` 环境变量（仅开发用途，勿写入代码）；
- 需要联网访问 `https://api.deepseek.com`。

## 三、命令矩阵（每次改动后的标准跑法）

| 目的 | 命令（每条跑 2 次取均值） |
|---|---|
| 主集混合（正面召回专项主战场） | `python tests/benchmark_golden.py --llm` |
| 边界集混合（跨领域防退化） | `python tests/benchmark_golden.py --edge --llm` |
| 3C 混合（3C 语体/口径改动） | `python tests/benchmark_golden.py --golden tests/fixtures/coldstart_digital3c_golden.csv --mode-key domain_digital3c_hybrid --llm` |
| hold-out（有数据后，每次只跑 1 次） | `python tests/benchmark_golden.py --golden tests/fixtures/holdout_3c.csv --mode-key holdout_3c_hybrid --llm` |

补充说明：

- 词典/临时检查不需要 LLM：`python tests/benchmark_golden.py`（主集词典）、
  `python tests/benchmark_golden.py --edge`（边界集词典）；
- 不想写历史/不想被 hold-out 计数：加 `--no-history`；
- hold-out 卷子只用于验收跑分，**临时检查一律加 `--no-history`**（自动计数按
  `holdout_*.csv` 文件名识别，防止词典检查误占验收次数）。

## 四、如何读结果

跑完后看最后几行：

```
整条情感准确率：78.9%（95% CI ±6.0pp）
对比（vs 上次 …）：整体 +1.2pp，Δ CI ±8.5pp（噪声内(±8.5pp)）
```

| 输出 | 含义 |
|---|---|
| `改善` | \|Δ\| 超出两侧 CI 组合宽度，统计学意义上的真提升 |
| `回退` | \|Δ\| 超出宽度且方向为负，需警惕并回滚 |
| `噪声内(±X pp)` | 变化在噪声范围，不判提升也不判回退（最常见） |
| `持平` | \|Δ\| < 1pp |
| `指纹不匹配` | 数据集内容变了（如 edge_set 版本升级），旧基线不可比，需重冻结基线 |

把每轮输出的 `run_id`（评测历史目录名，如 `20260815_141600`）和 2 轮均值发给我，
我负责对照基线出结论。

## 五、正面召回专项的验收口径（示例）

目标：主集 positive recall 68%→80%。n=50 的单侧 95% CI ≈ ±12.5pp，所以**单看
召回数字不能自证**；达标 = 证据组合：

1. 主集 positive recall 两轮均值 ≥ 目标（如 80%）且 **precision 不崩**（现 0.72~0.77，
   掉到 <0.65 即视为以假阳性换召回）；
2. 整体准确率不回退：主集 vs 基线 77.71%、边界集 vs 81.82%、3C vs 73.6%，
   均按 V3 status 判定；
3. hold-out 到位后叠加：同向提升且超其 CI（30~50 条 ≈ ±14~18pp）；
4. 错误样本人工抽检（我出清单，你确认无系统性新误判）。

## 六、常见问题

- **报"需要 API Key"**：先到应用侧边栏保存 Key，或设置 `OPENAI_API_KEY` 后重试；
- **报网络错误/超时**：检查代理与网络，稍后重试（脚本对批次失败有词典兜底，不中断）；
- **两次结果差很多**：属正常单轮噪声，以均值 + status 为准，不纠结单轮；
- **改了 prompt 后忘记录版本**：`PROMPT_VERSION` 常量在 `app/coding/llm_analyzer.py`，
  每次改动由我改并记录，你只管跑。
