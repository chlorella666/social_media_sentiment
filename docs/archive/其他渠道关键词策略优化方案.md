# 其他渠道关键词策略优化方案（B站 / 微博 / 小红书）

> 创建：2026-08-18 | 状态：**Phase 0 机制已落地（08-18）；B站经 A4 无需扩词
> （轨 B 结项）、微博 Phase 2 达标生效（08-19）、小红书暂缓**
> 关联：2.2 关键词策略（WebSearch 已闭环）、延后清单"跨渠道差异化关键词矩阵"、
> [评测中心审视报告](评测中心审视报告.md)（P1-1 模式动态化等，与本文解耦）

## 一、背景与目标

WebSearch 关键词策略已闭环（恋与深空/瑞幸达标），但**策略只作用于 WebSearch**：
`keyword_strategy.json`（同义词/额外查询/后缀池）仅被 `app/channels/websearch.py`
读取。其他渠道（B站/微博/小红书）走各自平台搜索机制，WebSearch 的"加后缀/改写
查询串"套路不适用：

- B站：搜索词 → 视频列表 → 按视频 ID 抓评论，评论与查询解耦，加"评价"只会降低
  视频召回；
- 微博：站内搜索 `q={keyword}`，结果集由平台排序决定，改写未验证且登录态风控敏感；
- 小红书：反爬最严，加词 = 加封号风险。

**目标**：在"采集配额 + 风控预算"内，用渠道自身的采集杠杆提升**有效供给率**
（保留/采集），按 **B站 → 微博 → 小红书** 顺序逐个验证、逐个生效。

**边界（不做）**：
- 不改 WebSearch 现有策略与开关行为；
- 不做客户端"排除词"误伤清洗（微博排除词留二期单独立项）；
- 不碰评测/黄金集纪律（纯采集层改动，无 LLM 判定变化）；
- 与 2.10（WebSearch 评论抓取 spike）完全独立。

## 二、已确认决策

1. 展开位置：**计划层**（向导确认时生成该渠道实际查询串，写入
   `channel_params[cid]["queries"]`），确认页可见、配额可估、报告可核对；
2. 开关模型：**任务级开关放主应用④渠道设置区**（与 WebSearch 现有开关同心智，
   提交任务时生效、不全局持久化）；**评测中心只管策略内容**（词组合）；
3. 策略配置 UI：评测中心「关键词策略配置」tab 用**内嵌 tabs**（WebSearch 默认
   选中，其余渠道各一面板），按渠道动态渲染表单；
4. 微博排除词：**二期**（清洗层规则需单独验证防误伤），一期只做查询词组合；
5. 小红书范围：**精简词建议 + 低效词避免**（不新增查询数量）；
6. 每渠道达标品牌数 **2 个**（沿用 2.2 分档 + URL 去重 + n≥30）；
7. 候选确认、备份/回滚、变更历史机制**复用现有 WebSearch 设施**。

## 三、核心机制：计划层展开

```text
向导④ 勾选「B站关键词优化」→ 提交时按 strategy.rules.bilibili 展开
  plan.keywords（品牌词）→ channel_params["bilibili"]["queries"] = 展开后查询串
  → 确认页显示每渠道查询数与开关状态 → 1.4 配额按展开后数量估算
  → bilibili.collect 优先读 channel_params["queries"]，缺省回退 plan.keywords
```

- `AnalysisPlan.channel_params[cid]["queries"]`：新增可选字段，向后兼容；
- 各 channel `collect` 改动一行（优先读 `queries`）；
- 报告"实际查询串"表升级为**按渠道展示**（2.9 透明度顺带覆盖）。

## 四、策略模型 v2（向后兼容 schema 1）

`app/channels/keyword_strategy.json`：schema 1 → 2，v1 字段原样保留，
新增 `rules.<channel>`：

```jsonc
{
  "schema": 2,
  "synonyms": { },            // v1 WebSearch，不动
  "extra_queries": { },       // v1 WebSearch，不动
  "suffix_pool": ["评价"],    // v1 WebSearch，不动
  "rules": {
    "websearch": { "prefer_suffix": [] },   // v1，不动
    "bilibili": {
      "queries": { "恋与深空": ["恋与深空 抽卡", "恋与深空 剧情"] }  // 每品牌 ≤5
    },
    "weibo": {
      "queries": { "恋与深空": ["恋与深空 话题词", "恋与深空 玩家"] }  // 每品牌 ≤5
    },
    "xiaohongshu": {
      "preferred": { "恋与深空": ["恋与深空", "恋与深空 攻略"] },  // ≤2，只精简不扩量
      "avoid": { "恋与深空": ["低效词"] }  // 人工确认后从关键词移除，不新增查询
    }
  },
  "updated_at": "…",
  "note": "…"
}
```

上限常量沿用 `MAX_EXTRA`（≤5）等，复用备份/回滚/变更历史。

## 五、数据层：渠道级候选反推

`app/core/keyword_effects.py` 的 `_extract_hints` 目前 websearch 硬编码，扩展为
渠道级：

- 新增 `extract_channel_candidates(history, channel)`：按 (品牌, 渠道, 查询串)
  聚合漏斗（数据已按 (channel, query) 记录，现成可用）：
  - B站：视频级有效率 ≥70% 且 n≥30 的"品牌×品类词"组合 → 候选 queries；
  - 微博：有效率 ≥70% 且 n≥30 的组合，且丢弃原因（营销/无关）占比低；
  - 小红书：有效率 <40% 且 n≥10 的词 → avoid 建议（不新增查询）；
- candidates 输出加 `channel` 列；评测中心候选确认按渠道筛选，
  确认写入对应 `rules.<channel>`（复用 `apply_candidates` + 备份）。

## 六、评测中心 UX（关键词策略配置 tab）

### 布局：内嵌 tabs

```text
🎛 关键词策略配置
┌──────────────────────────────────────────────────┐
│ 渠道：[WebSearch][B站][微博][小红书]（内嵌 tabs，WebSearch 默认）│
│ 说明：一句话解释该渠道策略（如"B站=视频发现词"）                    │
├──────────────────────────────────────────────────┤
│ 当前渠道面板（按渠道动态渲染）                                    │
│  状态行：该渠道策略内容概览（品牌数/词数，无全局开关）              │
│  表单区：品牌下拉(+新增) → 按渠道字段渲染 → 保存/删除              │
└──────────────────────────────────────────────────┘
下方固定区（所有渠道共用）：候选快捷写入（按渠道筛选）· 备份回滚 · 变更历史
```

### 要点

- WebSearch 面板 = 现有界面（老用户零学习成本）；
- 各渠道面板只显示自身字段（B站/微博 = 查询词组合；小红书 = 精简/避免词）；
- 候选确认按当前渠道过滤，写对地方；
- 变更历史带"渠道"字段（如"渠道：B站 · 品牌：恋与深空 · 写入 2 词"）；
- 总览小卡片：一行列出各渠道策略生效状态与品牌数（"哪些渠道有策略内容"）；
- 深链：`?tab=strategy&channel=bilibili`（主应用④开关旁链接直达对应面板，
  与现有 `?tab=strategy` 兼容）；
- 「关键词效果」页的前后对照同步支持**按渠道筛选**（对照必须在同一渠道内比）。

## 七、主应用④渠道设置区（任务级开关）

- 每渠道一个"关键词优化"开关（WebSearch 保留现有，其余新增），**默认关**；
- 勾选后提交时按策略展开并写入 `channel_params[cid]["queries"]`；
- 确认页摘要：每渠道"开关状态 + 查询数"；
- 开关旁提供"打开关键词策略配置"链接（深链到对应渠道面板）；
- 1.4 配额估算与每日上限按展开后查询数计。

## 八、受控对照与验收（沿用 2.2 口径）

- 对照：同品牌同渠道，关/开两轮任务 → 前后对照工具（需支持按渠道筛选）；
- 判定：基准有效率 <85% 走提升验证（提升 ≥5pp 且 n≥30、URL 去重）；
  ≥85% 走扩容验证（新词有效率 ≥80%）；
- **每渠道 2 个品牌达标 → 才进入下一渠道**；
- 每步全量回归 + 费用记录（无 LLM 新增，纯采集层）。

## 九、B站受控对照操作单（Phase 1 第一步）

1. 候选：`extract_channel_candidates(history, "bilibili")` 产出候选表；
2. 人工确认 2 个品牌的候选词（每品牌 ≤5 组合），写入 `rules.bilibili.queries`；
3. 基准轮：④ 不勾选 B站优化，跑品牌 A 任务（demo 之外的 bilibili 渠道）；
4. 优化轮：④ 勾选 B站优化，同参数跑品牌 A 任务；
5. 对照：关键词效果页按渠道=bilibili 筛选两轮 → 有效率/新增词判定；
6. 达标 → 品牌 B 重复 3~5；两品牌均达标 → 开启 B站策略生效 + 验收记录；
7. 全量回归 + todolist/决策日志更新。

## 十一、分阶段执行清单

### Phase 1~3 进展（2026-08-19）

- **Phase 1（B站）**：A4 去重修复后单关键词"瑞幸"有效率 100%、消费者声音
  占比 94.7%——扩词边际收益为"信息面扩展"而非提准（轨 B 评估结项，
  见关键词优化专项），B站不另做候选词对照；
- **Phase 2（微博）达标生效**：Cookie 实测可用；受控对照（扩容验证档）——
  **恋与深空**（5 词展开：祁煜/秦彻/联动/剧情/抽卡，新增词有效率 81.4%、
  E 9→29 +222%、n=35）✅ + **瑞幸**（联名/新品 2 词，有效率 94.4%、
  E 8→16 +100%、n=17 按 B3 多轮/比率稳定认可）✅；
  **华润万家未达标**（体验词命中营销、超市/店词命中媒体，56.8%<80%、
  E 不增、n=21）→ 候选已移除（无效词不进策略）；
  `rules.weibo.queries` = 恋与深空 5 词 + 瑞幸 2 词，**策略正式生效**；
- **Phase 3（小红书）暂缓**：无低效词数据（n≥10 且 <40%），重开条件 =
  真实采集数据 n≥30 或用户明确预算。

预估：Phase 0 约 1 天；每个渠道 Phase 约 1~2 天 + 对照任务等待；无新增 LLM 费用。

## 十二、风险与注意

1. **B站 API 稳定性**：公开 API 偶发限流，collect 已有失败降级，对照时注意重试；
2. **微博 Cookie 风控**：对照任务间隔开、控制查询总数；
3. **小红书**：只做词精简/避免，任何新增查询都视为高风险，需单独评估；
4. **策略内容误写**：候选确认 + 备份回滚兜底；变更历史带渠道便于审计；
5. **范围控制**：每渠道 2 品牌达标才进下一渠道，不达标不推进。
