# 评测中心改动类型引导方案（数据集选择的可执行化）

> 创建：2026-08-18 | 状态：待排期 | 来源：评测中心审视报告 P2-7（用户提问
> "如何判断该选哪个数据集"）
> 关联：评测中心审视报告（P1-1 模式动态化）、验证纪律 V4（跨领域双条件）、
> 2.6 模块化提准（module_*_hybrid 卷）

## 一、问题

模式 radio 从历史动态发现后平铺 **16 个键**（主集/边界集/3C/模块卷×3/
hold-out×4 × lexicon/hybrid），用户难以判断"这次改动该看哪个数据集"。
判断逻辑实际存在（改动范围 + 验证目的），但散在文档/纪律里，工具不引导。

## 二、目标

把"选数据集"从"靠人记规则"变成"工具按改动类型给推荐组合"，一键应用；
不删除任何模式键（都是裁判资产），不增加认知负担。

## 三、判断规则（推荐组合映射）

| 改动类型 | 推荐数据集（hybrid） | 强制/门槛卷 | 说明 |
|---|---|---|---|
| 领域级（如 3C 语体规则） | 目标领域卷（3C）+ 该卷 hold-out | 主集 lexicon | 目标提升 + 相邻不回退 |
| 模块级（数字产品/有形实物/服务内容） | 对应模块卷 + 该模块 hold-out | 主集 lexicon + 边界集 | 模块卷是模块化提准出口裁判 |
| 通用规则（提示词/词典/路由全局） | 主集 + 边界集 + 3C + 三模块卷 | 主集 lexicon | V4 跨领域双条件全量防回退 |
| 采集/清洗/关键词（不碰模型） | 不跑准确率 → 提示"看关键词效果/报告质量指标" | — | 省跑分，避免误用评测 |

默认配方：日常改动 = **主集 lexicon（门槛）+ 主集 hybrid + 边界集 hybrid +
3C hybrid**；声明"显著提升"必须加对应 **hold-out 同向**（工具在推荐时提示）。

## 四、UI 设计

侧边栏"筛选"区新增（在评测模式 radio 上方）：

1. **本次改动类型** radio：领域级 / 模块级 / 通用规则 / 采集清洗（默认"通用规则"）；
2. 下方展示**推荐数据集组合**（chip/多选，默认按规则勾选，可改）；
3. **一键应用**：把勾选写入评测模式（保持 lexicon/hybrid 各自存在）；
4. hold-out 卷在模式列表折叠进"留出卷（≤2 次）"分组；lexicon 卷加
   "门槛"徽标；采集清洗类型时显示提示文案，不默认勾选任何卷。

文案原则：一句话说明"为什么推荐这组"（如"通用改动需跨领域防回退"），
悬浮"？"解释 hold-out 与门槛卷。

## 五、实现清单（文件级）

### A. 规则与数据

- `eval_dashboard.py`：新增改动类型 → 推荐模式集合的常量映射
  （`CHANGE_TYPE_RECOMMEND`），键值来自 §三 表格；采集清洗类型返回
  提示文案而非模式集合。

### B. 侧边栏交互

- 改动类型 radio（session_state 记忆，默认"通用规则"）；
- 推荐组合 multiselect（默认按规则勾选，可增删）；
- "一键应用"按钮 → 把组合写为当前评测模式（若该模式无历史则提示先跑一次）；
- hold-out 分组：radio 选项按"常规 / 留出卷（≤2 次）"两组展示
  （动态发现时按 mode_key 前缀 `holdout_`/`_holdout_` 归类）；
- lexicon 卷加"门槛"前缀徽标（`_lexicon` 后缀）。

### C. 复用与兼容

- 复用 `_mode_options`（动态发现）、`MODE_LABEL/_mode_label`；
- 不删除任何 mode_key；AppTest 既有用例（模块模式/edge 模式）保持通过；
- 无 LLM 费用，纯前端 + 会话态。

## 六、测试与验收

1. `test_eval_dashboard` 新增：选择"模块级" → 推荐组合含
   `module_content_hybrid` 等且不含 3C；选择"采集清洗" → 提示文案、不勾选卷；
   一键应用后当前模式正确切换；
2. 保留既有用例（空历史/有数据/edge/模块模式/helper）；
3. 全量回归绿（当前 33/33 + 新增用例）；
4. 验收：开发者按改动类型 3 步内得到推荐组合；hold-out/门槛卷有明确标注。

## 七、范围与边界

- **不做**：删除/合并模式键、多模式并排对比、把引导做成通用 BI；
- 与主应用（向导/报告）解耦；不触碰评测数据层（eval_store 只读）；
- 若工作区有其他在途改动，排期执行时先与主线程同步再提交。

## 八、排期

0.5~1 天（规则映射 + 侧边栏交互 + 分组展示 + 测试/回归）；无新增 LLM 费用。
