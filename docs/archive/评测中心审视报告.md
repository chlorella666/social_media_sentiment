# 评测中心整体审视报告

> 创建：2026-08-18 | 状态：审视完成，改进建议待主对话排期
> 对象：app/eval_dashboard.py + 数据层 app/core/eval_store.py（黄金集评测中心，开发者工具）
> 关联：维度情感视图方案（见 §四 P1-3）、模块化提准（module_*_hybrid 模式）

## 一、总评

评测中心整体是一个完成度很高、工程功底扎实的开发者工具：数据分层、验证纪律、
可逆操作都做得好。但模块化提准后存在一个**必须修的 P1 遗漏**（模块模式在 UI
不可见），外加一批 P1/P2 改进点。

## 二、做得好的

### PM 侧

- 信息架构顺畅：概览（结论）→ 哪里好哪里差（短板）→ 情感表现（细看）→
  对比（验证）→ 关键词（调优）→ 策略（落地）→ 历史（审计），
  从"看结果"到"动手改"闭环；
- 小白友好：一句话人话总结、悬浮"？"术语解释、三步引导、n<30 标"参考"、
  短板清单；
- 2.2 关键词闭环完整：前后对照 + 达标判定（有效率 ≥5pp / 纯品牌词丢弃 <15%）+
  低效词删除建议 + 备份回滚——不只展示，能闭环决策。

### 工程侧

- 数据分层干净：`runs/<ts>/report.json` 全量明细 + `history.jsonl` 摘要，
  仪表盘只读摘要、明细按需加载；
- mode_key 隔离 + 冻结基线 + 指纹守卫（防新旧样本对比出错）+
  Wilson CI 噪声判定（改善/回退/噪声内）——验证纪律在 UI 有兑现；
- 策略编辑全链路可逆（自动备份/回滚/变更历史）；
- 有测试覆盖（test_eval_store / test_eval_dashboard 入回归）。

## 三、问题清单

### P1（建议尽快做）

**P1-1 模式选择漏掉模块模式（最要紧）**

- 现象：侧边栏模式 radio 硬编码只有 `lexicon / hybrid / edge_lexicon /
  edge_hybrid`；模块化提准新增的 `module_content/physical/service_hybrid`
  （以及 `domain_digital3c_*`）在 UI 里选不到——三模块跑分写进了历史，
  但评测中心看不到。M1~M5 收口时漏了这里。
- 建议：radio 选项改为从 `history` 动态发现 mode_key（按类型分组展示），
  `MODE_LABEL` 补上模块模式映射。

**P1-2 "细分维度"术语撞车**

- 现象：`GROUP_LABEL` 的 selectbox 叫"细分维度"，实际是渠道/领域/情感类别
  分组；与"分析维度"（价格价值/功能效果）概念冲突，模块化后更明显。
- 建议：改名"分组口径"，tooltip 说明"此处是渠道/领域/情感类别分组，
  不是分析维度"。

**P1-3 缺维度情感视图**

- 现状：逐维度 P/R/F1 数据（`dimension.per_dimension`：每维 n_gold/P/R/F1，
  键即中文维度名）和错误明细（`dimension_errors`）都已存在，但没有独立视图。
- 方案要点（详见侧线讨论，已确认）：
  1. 新增 tab"🧩 维度情感"，插在"情感表现"之后；深链支持 `?tab=dimension`；
  2. 五个子块：指标卡行（微平均 F1/精确命中率/维度样本 n/旧口径提及 F1）、
     逐维度 P/R/F1 表（n<30 参考、n≥30 且 F1<0.5 短板，按 F1 升序）、
     维度情感分布图（每维 gold vs pred 正负计数，需 benchmark 新增
     `dimension_sentiment_dist` 字段，旧 run 降级提示）、
     任选两次运行维度对比（独立 selectbox key）、维度错误下钻
     （维度下拉 → dimension_errors 明细）；
  3. 数据层改动仅 benchmark 新增分布字段（向后兼容），无 LLM 费用。

**P1-4 错误下钻入口太深**

- 现象：错误明细只藏在"运行对比"tab（默认 cur=最新运行，数据其实可见），
  但"看最新运行错在哪"是高频操作，位置不直观。
- 建议：在"哪里好哪里差"或概览加直达入口。

### P2（值得做）

- **P2-1 冻结基线在 UI 无展示**：`eval_store` 有 `compare_baseline` /
  `load_frozen_baseline`，但仪表盘没读 `vs_baseline`——回归门槛
  （词典 50.9%、模块基线）这个"裁判"在 UI 里不可见。
  建议概览加"vs 冻结基线"指标/徽标。
- **P2-2 运行历史名不副实**：只列当前模式的 runs；建议标注"当前模式"
  或加"全部模式"筛选。
- **P2-3 运行对比的下拉是 run_id（时间戳串）**：建议显示"时间 · 准确率 · n"。
- **P2-4 短板判定逻辑重复 3 处**（`_plain_summary` / `_segment_rows` /
  页面内联循环），阈值 0.75 与 REF_N 分散——建议收敛为一个 helper，
  防口径漂移。
- **P2-5 by_flag 错误筛选的小 bug**：错误样本 `flags` 是逗号串，
  "筛选段"按整串匹配，单选一个语言现象筛不出来；建议按逗号拆分后筛选。
- **P2-6 关键词扫描是同步子进程**（最长 600s），大目录会卡 UI 无进度；
  建议至少加 spinner/说明，后续可异步。
- **P2-7 数据集选择缺引导（2026-08-18 登记）**：模式 radio 动态发现后
  平铺 16 个键，用户难以判断"该选哪个数据集"——按改动类型（领域级/模块级/
  通用规则/采集清洗）自动推荐数据集组合并一键应用，hold-out 折叠为"留出卷
  （≤2 次）"，lexicon 门槛卷加徽标。方案见
  [评测中心改动类型引导方案.md](评测中心改动类型引导方案.md)。

### P3（记录项）

- 运行报告明文含原文，页面已提示"仅本机"，建议在数据目录说明再明确
  "勿同步/分发"；
- 历史增长后每次 rerun 全量重算摘要对比，量大时偏慢（可缓存）；
- 负面召回阈值 <0.6 等口径硬编码，可参数化。

## 四、建议的实施顺序

1. **P1-1 模式动态化**（模块跑分不可见，优先级最高，约半天）；
2. **维度情感视图 + P1-2 术语改名**（方案已确认，0.5~1 天）；
3. **P1-4 错误下钻前置**（小）；
4. **P2 批**（基线展示、历史标注、run 标签、短板逻辑收敛、by_flag 修复）；
5. **P2-7 改动类型引导**（按改动类型推荐数据集组合，0.5~1 天）；
6. 以上全部并入全量回归 + 新增/更新 test_eval_dashboard 用例。

预估：P1 合计约 1.5~2 天；P2 批约 1 天；P2-7 约 0.5~1 天；无新增 LLM 费用。

## 五、不建议做的（防过度工程）

- 不要把评测中心做成通用 BI/大屏——它是开发者工具，保持"结论先行 + 可下钻"；
- 不要为旧 run 回填维度分布等新字段——降级提示即可，不值得写迁移；
- 模式选择动态化即可，不必做多模式并排对比
  （现有单模式 + 跨模式趋势图已够用）。

## 六、结论

评测中心地基好（验证纪律、可逆操作、小白引导），**最要紧的是补上模块模式的
可见性（P1-1）**，然后按已确认方案做维度情感视图并顺手修术语撞车（P1-2/3）。
P2 批是低成本高回报的打磨。建议在主对话作为"评测中心增强"专项排期，
与 2.8 自定义维度统计方案解耦执行（互不影响）。
