# 采集透明度方案（Collection Transparency）

> 创建：2026-08-18 | 状态：**已执行完成（2026-08-18）** | 关联：2.2 采集漏斗、
> 2.9 关键词透明度、关键词优化与报告质量提升方案（消费者声音）、
> 微博采集插桩诊断（2026-08-18，华润万家 20→6 差异）

## 一、问题与目标

**问题**：用户设置每关键词采集 20 条，实际报告可能只有 6 条，且无任何解释。
插桩诊断证明差异**可解释、可归因、可行动**（华润万家×微博：API 返回 14 张
正文卡、9 条超出时间窗被静默过滤、页 2 起无正文卡）。

**目标**：让"为什么没采满"在报告中**可见（采集漏斗）、可解释（原因分类）、
可行动（建议：放宽时间窗/增加关键词）**，消除"系统是不是坏了"的疑问。

**定位**：这是**采集透明度**（产品能力），不是把调试日志暴露给用户；
`SMS_DEBUG_WEIBO=1` 的逐页细账保留为开发级排障工具。

## 二、方案设计

### 2.1 数据层：ChannelResult 增 `collection_stats`

```python
class ChannelResult(BaseModel):
    ...
    collection_stats: dict[str, Any] = Field(default_factory=dict)
```

字段（各渠道只填自身可观测项，缺省显示 "—"）：

| 字段 | 含义 |
|---|---|
| requested_limit | 该渠道每关键词配置上限 |
| api_returned_cards | API 返回卡片总数 |
| mblog_cards | 正文卡（type9）数 |
| skipped_other_type | 非正文卡片数（不计 dropped） |
| skipped_dup | 重复返回跳过数 |
| skipped_ad | 广告（ad_marked）跳过数 |
| skipped_out_of_range | 超出时间范围跳过数 |
| kept | 实际保留 |

### 2.2 静默跳过转 dropped（采集层透明化）

- 微博：`超出时间范围` / `广告（ad_marked）` / `重复返回（同帖）` 从静默
  `continue` 转为 dropped 记录（原因分类）——2.2 漏斗与关键词效果页自动可见；
- B站：`超出时间范围` 同样转 dropped；
- 非正文卡片**只进 stats**（不是"内容"，不进 dropped）；
- WebSearch 已有完整 cleaner 丢弃原因，本轮不动。

### 2.3 报告/结果页"采集说明"区块

- 结果页：当 `实际保留 < 配置上限` 时显示一行摘要（"采集 X/目标 Y · 查看原因"）
  + 可展开明细（按渠道：目标/API 返回/各原因计数/建议）；
- HTML 报告：新增"采集说明"小节（仅缺口时渲染），含行动建议文案；
- Excel：丢弃明细 sheet 自动获得新原因（超窗/广告/重复）；汇总 sheet 加
  "采集说明"行；
- Word：一行摘要（可选）。

### 2.4 范围边界

- 只做微博 + B站 的采集层补全；WebSearch 不动（已有漏斗）；
- 不做实时诊断面板、不做逐卡原文展示、不改 LLM 判定、不新增费用；
- 旧任务 result.json 无 collection_stats → 全部兜底，向后兼容。

## 三、专业审核（漏洞与对策）

### 漏洞 1（关键）：采集层 dropped 会污染"补采触发"与"2.2 判定口径"

- 把"超出时间范围/广告/重复"计入 dropped 后，`drop_rate = 丢弃/采集` 会升高，
  可能触发 pipeline 补采（超窗帖补采也采不到 → 白跑一轮）；
- 2.2 受控对照的"有效供给率 = 保留/采集"口径也会被采集层因素稀释。
- **对策：双层口径**——① 展示层用全量漏斗（含采集层原因，透明）；
  ② 决策层（补采触发、短板判定、2.2 验收）只用"质量丢弃"
  （不相关/文本过短/样板/官方/LLM 不相关），排除
  `重复`（A4 已做）+ `超出时间范围` + `广告`；
  统一 helper `is_quality_drop(reason)`。

### 漏洞 2：字段口径不齐导致展示混乱

- 各渠道 stats 字段不同（微博有广告，B站无）→ 报告需对缺失字段显示 "—"，
  并注明"该渠道无可观测项"。

### 漏洞 3：缺口提示的噪音

- 只在 `实际保留 < 配置上限` 时展示；多渠道任务按渠道逐行列出；
- 文案要"如实 + 可行动"：平台限制（API 给不满）如实说明，同时给
  "放宽时间窗/增加关键词"建议，不甩锅给用户。

### 漏洞 4：向后兼容

- ChannelResult/ReportBundle 新字段 default_factory；旧 result.json 缺失时
  `get()` 兜底；采集说明仅在 stats 存在时渲染。

### 漏洞 5：不新增隐私暴露

- 采集说明只展示计数与原因，不新增原文；丢弃明细原有原文展示保持不变。

## 四、执行清单

1. `models.py`：ChannelResult.collection_stats；
2. `weibo.py`：统计填充 + 静默跳过转 dropped（超窗/广告/重复）；
3. `bilibili.py`：超窗转 dropped；
4. `pipeline.py`：`is_quality_drop()` 统一补采/决策口径（排除 重复/超窗/广告）；
5. `html_report.py` + 模板：采集说明区块（缺口时）；
6. `main.py` 结果页：摘要 + 展开明细；
7. 测试：模型缺省、is_quality_drop、报告渲染（有/无 stats、缺口/满额）；
8. 全量回归 + 文档更新（本方案状态、决策日志、todolist、项目方案）。

## 五、验收

1. 微博任务实际 < 配置时，结果页/HTML 出现采集说明（含各原因计数与建议）；
2. 采满时不出说明（无噪音）；
3. 补采触发与 2.2 口径不受采集层原因污染（is_quality_drop 单测）；
4. 旧任务无 stats 正常渲染；
5. 回归绿 + 无新增 LLM 费用。

## 六、执行结果（2026-08-18）

- **数据层**：ChannelResult 增 `collection_stats`（缺省空，向后兼容）；
- **采集层**：微博/B站把静默跳过转 dropped（原因：超出时间范围 /
  广告（ad_marked）/ 重复返回（同帖））并填充 stats（requested_limit /
  api_returned_cards / mblog_cards / skipped_* / kept）；
- **决策口径**：`is_quality_drop()` 统一补采触发与 2.2 判定——排除
  重复/超窗/广告（展示漏斗仍含全量原因）；
- **展示层**：结果页"采集说明"expander（缺口时）+ HTML 报告"采集说明
  （为什么没采满）"区块（含原因与建议：放宽时间窗/增加关键词）；
- **验证**：华润万家×微博 20→6 已可解释（API 正文 14 条、超窗 9 条被过滤、
  页 2 无正文）；tests/test_collection_transparency.py 4 项入回归；
  全量回归 34/34 + 词典门槛 PASS；无新增 LLM 费用。

## 七、扩展落地（2026-08-19：小红书 + WebSearch + 人工筛选路径修复）

### 背景

用户华润万家试跑（20260819_001407，微博保留 19 / 丢弃 23）未出现"采集说明"，
落盘 `collection_stats={}` —— stats 在人工筛选（review）路径被丢：
worker 快照只存 posts/drops/warnings，`_apply_exclusions` 重建
`ChannelResult` 时未恢复 stats。

### 本次改动

1. **小红书补齐**（与微博/B站同构）：
   - 静默跳过转 dropped：缺链接 / 重复返回（同帖）/ 超出时间范围；
   - `collection_stats` 覆盖成功、空结果、风控即停全返回路径；
   - 修复详情/评论拉取风控分支 `exc` 未定义隐患（真触发风控会 NameError）。
2. **WebSearch 按边界补齐**：
   - 官网域名黑名单：保留逐条 dropped + `skipped_official` 计数（与品牌强相关、
     可行动）；
   - 子渠道域名过滤：只累计 `skipped_domain_filter` 计数，不逐条记明细
     （防丢弃明细被无关结果刷屏、JSON 膨胀）；
   - 重复跳过计数；`empty_queries` / `risk_stop` 计数（风控提前结束可解释、
     可行动）；空结果/风控提前结束返回也带 stats；
   - `_collection_notes` 新增 WebSearch 专用原因/建议（官网黑名单、子渠道域名
     过滤、空查询、风控信号），仅缺口时展示。
3. **人工筛选路径修复**（根因）：
   - `_write_snapshot` 持久化各渠道 `collection_stats`；
   - `_apply_exclusions` 重建 `ChannelResult` 时恢复对应渠道 stats；
     旧快照无该字段兜底空（向后兼容）。

### 验收

1. 小红书任务实际 < 配置时，结果页/HTML 出现采集说明（含超窗/重复/缺链接原因）；
2. WebSearch 任务（含子渠道）实际 < 配置时出现说明，官网黑名单/子渠道过滤/空查询/
   风控原因可解释；
3. 人工筛选（review）流程重建后 stats 不丢，采集说明可渲染；
4. 采满不出说明（无噪音）；旧任务无 stats 正常渲染；
5. 回归：采集透明度 6 项 + WebSearch 鲁棒性 10 项全绿。

### 遗留

- 历史任务 result.json 无 collection_stats → 不自动补，需重跑后采集说明才出现；
- WebSearch 子渠道域名过滤暂不逐条记 dropped 明细（计数口径已覆盖缺口解释），
  如后续需要逐条审计再按需加。
