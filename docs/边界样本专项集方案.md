# 边界样本专项集方案（Edge Set）

> 状态：草案 v0.1（2026-08-13）| 服务对象：2.3 情感准确率专项（提示词迭代 / 置信度校准 / 边界样本回归）
> 关联：[抽样与标注规范](抽样与标注规范.md) v1.0（主集流程完全复用）· [黄金集 v1.1](评测记录.md) · [todolist 2.3](../todolist.md)

---

## 一、定位与目标

主集（黄金集 v1.1，175 条主评分）是"防退化裁判"：负责整体/渠道/领域/情感类的回归门槛。
边界样本专项集（下称"边界集"）是"2.3 提升裁判"：专门判定反讽/黑话/方言/长文本/emoji 主导/
低置信文本的提示词迭代是否真的变好。

**两个裁判各司其职、互相独立**：

- 主集管"别改坏"（回归必须绿）；
- 边界集管"改没改好"（专项提升是否达标）；
- 边界集独立成文件，**不计入主评分，不污染主集基线**。

## 二、组成与抽样量（共约 300 条，2026-08-13 已确认）

| 子集 | 建议量 | 用途 | 来源说明 |
|------|--------|------|----------|
| 反讽/阴阳怪气 | 50 | 2.3 提示词迭代核心 | 最难、歧义最高；高歧义 100% 复核 |
| 黑话 | 50 | 提示词 + 词典 | 可复用现有 26 条 + 定向补齐 |
| 方言 | 50 | 提示词迭代 | 需定向来源（粤/川渝/东北） |
| 长文本（>100 字） | 50 | 长文情感聚合 | 微博长文/知乎回答/B站长评 |
| emoji 主导 | 30~50 | 语体多样性 | 可复用现有 22 条 + 定向补齐 |
| 低置信/临界歧义 | 50 | 置信度校准 | 词典打分 0.55~0.95 区间样本 |

**抽样量依据**：30 条时 95% 置信区间约 ±17pp，50 条约 ±14pp，只能看"大方向"。
因此判定采用"方向 + 多轮对比 + 人工抽检"组合，不设单次硬门槛（可 `--strict-edge` 开启）。

## 三、定向来源（怎么采）

- **反讽**：微博/小红书反讽信号词（"太棒了""真好呢""谢谢您嘞"）+ B站评论；
  `tests/sample_golden_set.py` 已有 irony_hint 启发式可直接复用；
- **黑话**：`app/coding/lexicon_v2.py` 黑话词表 + 现有样本 + 游戏社区词
  （保底/狗叠/圣遗物/yyds 等）在微博/B站/小红书定向搜；
- **方言**：微博地域话题 + 贴吧方言帖，WebSearch 定向；
- **长文本**：从已有采集数据按长度筛 + 定向抓长评；
- **emoji 主导**：emoji 占比高的短文本（现有 22 条 + 定向补齐）；
- **低置信**：用词典对候选语料打分，抽阈值附近样本（天然偏歧义，无需配平情感分布）；

统一约束（复用主集规范 §二）：

- 必须真实采集数据，记录平台/链接/作者/时间/批次，可回溯；
- 清洗丢弃样本不进本集（归清洗验证集）；
- 每个子集记录采集日期与关键词，避免"网络词时效"带来的不可复现。

### 采集渠道与配额（2026-08-13 已确认：微博 / 小红书 / WebSearch / B站）

定向采集是"广撒网再筛"：原始采集量按 2~3 倍超采（反讽信号词命中率可能仅三成）；
低置信子集不占采集配额（直接对已有语料做词典打分抽取）。

| 子集 | 目标有效样本 | 预估原始采集 | 渠道分配（原始量） | 关键词思路 |
|------|------|------|------|------|
| 反讽 | 50 | ~150 | 微博 60 / 小红书 40 / WebSearch 50 | "太棒了""真好呢""谢谢您嘞"等信号词 |
| 黑话 | 50 | ~100 | 微博 40 / 小红书 30 / WebSearch 30 | 保底/狗叠/圣遗物/yyds 等圈内词 |
| 方言 | 50 | ~100 | 微博 50 / WebSearch（含贴吧）50 | 粤语/川渝/东北特征词 + 地域话题 |
| 长文本 | 50 | ~70 | WebSearch 30 / 微博 20 / B站 20 | 筛选 >100 字长评/长文 |
| emoji 主导 | 50 | ~100 | 微博 50 / 小红书 40 / WebSearch 10 | emoji 占比高短文本 |
| 低置信 | 50 | 0（已有语料打分抽取） | — | 词典得分 0.55~0.95 区间 |
| **合计** | **300** | **~520** | 微博 ~220 / 小红书 ~110 / WebSearch ~190 / B站 ~20 | — |

配额换算（现有渠道限制：微博 30 条/关键词、小红书 20 条/关键词、WebSearch 50 条/关键词）：

- 微博 ≈ 220 条 → 约 8 个关键词 × 30，分 2~3 天执行（降风控风险）；
- 小红书 ≈ 110 条 → 约 6 个关键词 × 20；
- WebSearch ≈ 190 条 → 约 4 个关键词 × 50（含知乎/贴吧子渠道，零登录）；
- B站 ≈ 20 条（公开 API，零登录，仅长文本补充）。

## 六、与主集的关系

- 独立文件 `tests/fixtures/edge_set_v1.csv`，**不进主集、不计入主评分**；
- `tests/benchmark_golden.py` 增加 `--edge` 模式：每类准确率/P/R/F1 + 总体，
  写入评测中心独立历史（`mode_key="edge"`）；
- 主集继续负责"渠道/领域/情感类防退化"，边界集负责"专项提升"；
- 边界集同样冻结版本（v1），升级走版本化，禁止边评边改。

## 七、基线管理

1. 建集后先跑基线：词典直判 + 混合（每类 + 总体），记入 `docs/评测记录.md` 与评测中心；
2. 新增 `tests/fixtures/baseline_edge_lexicon.json`（✅ 2026-08-13 冻结：46.4%，
   n=220，按子集见文件；dialect 17 / emoji 26 为参考级）与
   `baseline_edge_hybrid.json`（✅ 2026-08-13 冻结：77.73%，脱敏口径；
   irony 67.3% 为首要提升目标，dialect/emoji 参考级）：
   每类容差建议 3~5pp、总体 1~2pp；
   **strict-edge 采用 A 档（2026-08-13 已确认）：只提示 + 人工验收，不设硬门槛**；
3. 2.3 每次改动验收三步：
   - 主集回归必须绿（防退化）；
   - 边界集看专项提升：**2.3 收尾时看连续 2 轮对比，每类 ≥+5pp 才算达标**，
     未达标进入人工验收（小样本噪声默认只提示不拦截；n<30 子集仅参考）；
   - 低置信子集做分桶校准检查（按置信度分桶，准确率应单调）；
4. 跌破基线复用 `--accept-baseline` 显式接受 + 记录理由；
5. 边界集内容变更后，跨版本对比被 golden 指纹守卫自动拦截（2.1 已有机制）。

## 九、风险与防护

| 风险 | 对策 |
|------|------|
| 小样本波动（±14pp） | 只用"方向 + 多轮 + 人工"，默认不设单次硬门槛 |
| 定向采集引入偏差（如只采到"明显反讽"） | 记录来源/日期/关键词；提升判定看的是同一批样本改前改后，偏差可抵消 |
| 方言/黑话时效性（网络词过时） | 记录采集时间，版本冻结 |
| 过拟合边界集 | 冻结 + 人工验收保留；争议集单独归档不参与评分 |
| 主集与边界集混淆 | 独立文件/独立 mode/指纹守卫，回归清单明确区分 |
| 采样池漂移（data/reports 随任务增长，同 seed 重生成出不同样本） | 以已生成工作表/最终
  fixture 为冻结源；任何重生成必须先校验 text_id 集合（2026-08-13 实测漂移 168/300，
  临时移出新增报告目录复现原始池后修复） |
| 现象采集关键词 ≠ 品牌（「唔该」「😡😡 太坑了」等伪品牌污染品牌列/领域列） | 现象样本
  品牌列置空、关键词列保留；领域标签仅作维度列选择参考，不适用则留空；修复脚本
  `tests/fix_edge_brand_meta.py` 带前后一致性校验（2026-08-13 已落地，120/300 行） |
