# 叙事归因聚合与共现网络重构方案

> 创建：2026-08-19 | 状态：**已执行（2026-08-19，回归 34/34 + 黄金集门槛 PASS）** |
> 关联：2.12 报告证据链（三端渲染/证据卡）、2.3 情感准确率（n 守卫纪律）、
> 报告"情绪来源与讨论结构"区块（共现网络） | 执行顺序：Part A → Part B

## 一、背景与目标

**问题 A（叙事/归因粒度错误）**：报告"叙事框架与归因（LLM 高级分析）"现在渲染
逐条表格（文本/叙事框架/归因主体一行一条），属于原始数据粒度；逐条明细 Excel
已有（`叙事框架`/`归因主体` 两列），报告应提供**统计**而非复读明细。

**问题 B（共现网络无信息）**：当前网络图 = PMI top30 词对 + spring_layout 随机
撒点 + 全边 + 30 个标签全显示，结果是"毛团"——没有中心、没有分组、标签互相
覆盖，颜色只表达情感，读不出"讨论分几坨、每坨多大"。

**目标**：
1. 叙事归因从"逐条表"升级为"两张聚合图 + 规则解读"，一眼回答"用户主要把问题
   归给谁、哪类叙事×归因组合是风险热点"；
2. 共现网络重构为"话题簇 + 簇榜单"，图看结构、表看数字；
3. 三端一致（HTML/Word/App），沿用 n 守卫纪律，旧任务向后兼容；
4. 零新增 LLM 费用（聚合与解读全走规则）。

## 二、公共数据口径

| 项 | 口径 |
|---|---|
| 样本范围 | 仅 `plan.narrative_enabled=True` 且 LLM 编码过的文本（`method=llm`）；词典模式无叙事数据，区块不渲染 |
| 归因主体 | 固定词表 8 类：政府/企业/个人/制度/技术/社会/自然/不明确 |
| 叙事框架 | 新闻五框架：冲突/人情味/归因/经济后果/道德 |
| 情感 | 与报告情感统计同一口径（`stat_items`，含 need_review 未复核按模型判定） |
| 未给出 | `attribution=None` / `narrative=None` 的文本不计入对应维度，总数单独记录（`gave_attr`/`gave_frame`） |
| 分母 | 归因桶百分比分母 = `gave_attr`；框架桶分母 = `gave_frame`；热力图格分母 = 该格文本数 |
| 向后兼容 | 旧 result.json 无 `narrative_stats`/`node_count`/`cluster` 时 `get()` 兜底，新区块不渲染、旧图不崩 |

## 三、Part A：叙事归因聚合图

### 3.1 数据层（pipeline.py `build_summary`）

在 `build_summary` 中新增 `narrative_stats`（确定性规则，零 LLM 调用）：

```python
narrative_stats = {
    "total": 111,        # 样本范围 = stat_items 中 method=llm 且叙事字段非空的文本数
    "gave_attr": 98,     # attribution 非空
    "gave_frame": 95,    # narrative 非空
    "unclear": 12,       # attribution == "unclear"
    "by_actor": [
        {"actor": "enterprise", "count": 40, "positive": 5, "neutral": 8,
         "negative": 27, "negative_rate": 0.675, "ref": False},
        # ref=True 当 count<10（样本有限）
    ],
    "by_frame": [
        {"frame": "conflict", "count": 30, "positive": 2, "neutral": 6,
         "negative": 22, "negative_rate": 0.733},
    ],
    "frame_actor": {
        "conflict": {"enterprise": {"count": 12, "negative": 9,
                                    "negative_rate": 0.75}},
    },
}
```

排序规则：`by_actor` 按 `negative` 降序，`unclear` 固定最后；`by_frame` 按
`count` 降序。聚合只用 `stat_items`（与情感统计同源）。

### 3.2 图 A-1：归因主体分布（主图）

- **类型**：横向堆叠条形（`go.Bar(barmode="stack")`），Y 轴 8 个归因主体（中文名，
  复用 `excel_writer.ATTRIBUTION_CN`），X 轴条数；
- **图例/颜色**：堆叠段 = 文本情感，沿用 `SENTIMENT_COLORS`（负面 `#dc2626` /
  中性 `#94a3b8` / 正面 `#16a34a`）；
- **标注**：柱末端 `n=x · 负面率 y%`（仅 count≥3 的桶）；
- **n 守卫**：桶 count<3 → 整体透明度 0.35 灰化（数据如实画，解读不引用）；
  3≤count<10 → 柱名加"样本有限"（ref=True）；
- **图例说明**：`颜色=文本情感；数值=条数与负面率`，标题"归因主体分布
  （用户主要把问题归给谁）"。

### 3.3 图 A-2：叙事框架 × 归因主体热力图（副图）

- **类型**：`go.Heatmap`，行 = 5 框架，列 = 8 归因主体；
- **字段**：z = 负面率（0~1），text = `n · 72%`（count≥3 时），count<3 → z=NaN、
  text="—"（灰格 `#e5e7eb`，`colorscale=[[0,"#ffffff"],[1,"#dc2626"]]`）；
- **总计**：最右"总计"列 + 最下"合计"行（浅色底），**各自显示该列/该行的负面率**
  （分母分别为该 actor / 该 frame 的文本总数），右下角格为整体负面率
  （分母 = `gave_attr`）；总计行列从 `frame_actor` 交叉表推导，不单独重算；
- **图例**：colorbar 标题"负面率"，格内数字=条数；
- **n 守卫**：全局 `total < 10` 不渲染（见 §3.5）。

### 3.4 区块呈现与规则解读

- 移除 **HTML** 的 `narrative_rows` 逐条表（Word/App 结果页本无此表，是**新增**
  聚合区块而非替换）；逐条明细 Excel 保留不动；
- 区块标题："叙事框架与归因（LLM 高级分析）"，下方小字"仅对 LLM 精分析过的
  文本执行（成本控制设计）；归因/框架为固定词表";
- **规则解读（零 LLM 成本，复用"发现"文案风格）**：
  - 取"negative≥3 且 count≥10 **且 negative_rate≥50%**"的前 2 个归因主体，输出：
    `用户主要将问题归因于【企业】（负面率 x%，n=y）；其次【技术】（负面率 a%，n=b）。`；
    不满足负面率下限的主体只报事实、不断言："讨论量最高的归因主体【X】
    （负面率 y%，n=z）"（attribution 框架含正面归因，如"企业做得好"）；
  - 热力图取"负面率 ≥60% 且 count≥10"的前 2 个格子：
    `【冲突 × 企业】类文本负面率 x%（n=y）为风险热点。`；
  - 无达标桶 → 降级为方向性提示"归因样本有限，建议扩大采集或人工复核后再判断"；
  - `unclear_ratio > 30%` → 追加用户向提示"归因不明确的样本占比较高，
    建议人工复核样本"（"优化提示词"类开发向建议只记入内部文档/日志，不进报告）。
- **链路约束**：解读由渲染层 `narrative_insight_text(summary)` 确定性生成，
  **不进 `chart_insights`、不新增 `CHART_IDS`、不改 LLM `generate_insights` prompt**
  （避免改动 LLM 输出契约与 token 成本）。

### 3.5 n 守卫规则汇总（Part A）

| 层级 | 规则 |
|---|---|
| 全局 | `narrative_stats.total < 10` → 不渲染两图，仅显示"叙事/归因样本仅 N 条，样本不足"一行 |
| 归因桶 | count<3 灰化不参与解读；3≤count<10 标"样本有限"；解读只引用 count≥10 且 negative≥3 |
| 热力图格 | count<3 不填色（灰格 "—"）；风险热点判定要求 count≥10 且负面率≥60% |
| 不明确 | 保留"不明确"桶，固定画在最底；`unclear_ratio>30%` 出规则提示 |

## 四、Part B：共现网络重构

### 4.1 数据层

1. `tokenizer.py` `build_cooccurrence` 增加**可选参数** `return_counts=False`
   （默认签名与返回值不变，兼容 tests/test_tokenizer.py 现有调用）；
   `return_counts=True` 时返回 `(edges, node_count)`，`node_count` 复用内部
   `word_counter`（文档频次），仅在 `build_summary` 内传 True 解包；
2. `build_summary`：网络输入从 `cooccurrence` 顶 30 词对收缩为**节点 top 20**
   （按 node_count 降序），边按 PMI 降序取**直到覆盖 ≥8 个节点或取满 20 条**
   （执行时修订：25% 比例规则把罗技 15 边砍到 5 边、节点 7<8 误伤降级；
   改为节点门槛驱动，小样本不误伤、大图仍封顶 20 条；
   2026-08-19 修订 2：门槛随词对榜联动升至 15 节点，<15 走词对榜）；
   社区发现与簇统计放 **build_summary 层**（`app/core/topics.py`）：
   `networkx.community.louvain_communities(g, seed=42)`，簇数收敛后截断为 3~5；
   超过 5 簇时最小簇合并为**"其他"灰簇**（固定规则，避免每次报告合并结果漂移）；
   （执行时修订：簇文档数需按"词并集"逐文本扫描，渲染层拿不到文本，
   故从渲染层移入数据层；渲染层只消费 `topic_clusters` 结果。）
3. **话题簇榜单**在渲染层由 `(cluster, node_count, node_negative_rate)` 派生，
   不进 summary（三端各自调用同一 helper）。

### 4.2 图 B-1：话题共现网络

- **节点**：大小 = `sqrt(node_count)` 归一；颜色 = 话题簇（定性色板
  `["#6366f1","#f59e0b","#10b981","#ef4444","#8b5cf6"]` 前 N 色）；
  边框 = 情感倾向（沿用 `_node_color` 的 0.6/0.4 阈值：红/绿/灰）；
- **边**：只画显著边（§4.1 的 top-k），簇内边同簇色淡、簇间边灰色虚线；
- **标签**：只标每簇 top 2~3 个 hub 词（按 度数×node_count 排序），其余节点
  悬停可见（HTML/App）——保证 Word 静态图不糊脸；
- **悬停**：词 · 簇名 · 文档数 · 负面率 · 主要维度；
- **图例**：簇色（"簇 1：<簇名>"）+ 边框情感说明。
- **静态图适配**：Word/PNG 版柱高下限与标注字号保证可读；A-1 柱端标注
  （n/负面率）在 Word 版可省略（HTML 悬停与 Excel 明细已覆盖），
  A-2 格内数字与颜色是唯一信息通道、必须保留。

### 4.3 话题簇榜单（必选组件）

| 列 | 来源 |
|---|---|
| 簇名 | 簇内 node_count 最高的词 |
| 代表词 | 簇内 top3（按 度数×node_count） |
| 涉及文本数 | 至少包含簇内**任一节点词**的独立文本数（并集）。执行时修订：
  词频求和会重复计数（OPPO"数码"簇求和 29 vs 独立文本 13，2026-08-19 用户质疑） |
| 负面率 | 簇内节点 负面文档数/（正+负） |

按文档数降序，渲染在**网络图下方**（HTML/Word/App 三端同构）；图看结构、
表看数字。

### 4.4 n 守卫与降级（Part B）

统一 helper（html_report.py 导出，三端共用）：

```python
def cooccurrence_plan(summary) -> dict:
    """返回 {"kind": "network"|"ranking"|"skip", "reason": str}"""
```

| 条件 | 行为 |
|---|---|
| `total_items < 20` | kind=skip，不渲染任何图（区块整体不出现） |
| 边数 <12 或 节点 <15 | kind=pairs，**话题词对榜**（词对+共现文本数+PMI，按共现数降序） |
| `networkx` ImportError | kind=pairs（try-import 兜底，缺包也能出词对榜） |
| 单簇占比 >90% | kind=pairs，提示"讨论未形成明显话题簇" |
| 节点文档数 <5 | 节点灰化"样本不足"，不参与负面率着色与边框 |
| 其余 | kind=network，网络图 + 簇榜单 |

`reason` 字段随降级结果渲染出来，显式标注"已显示话题词对榜（未聚类）"，
避免用户误以为词对榜就是网络图。小图不强行聚类（2026-08-19 用户拍板 A）。

## 五、专业审核（漏洞与对策）

### 漏洞 1：归因分母口径混乱（"未给出"稀释百分比）
- **对策**：百分比分母各自取 `gave_attr`/`gave_frame`，与"未给出"互斥；
  热力图格内百分比分母 = 格文本数；图表注脚写明口径。

### 漏洞 2：Louvain 随机性导致每次报告簇不一致
- **对策**：`louvain_communities(g, seed=42)` 固定种子；簇数收敛后截断
  3~5，超出时按节点数合并最小簇；同一任务重出报告结果可复现。

### 漏洞 3：Word 静态图标签糊脸
- **对策**：标签只标每簇 top2~3 hub 词；节点尺寸下限保证可读；
  静态图信息不足处由簇榜单补齐。

### 漏洞 4：旧 result.json 无新字段
- **对策**：`summary.get("narrative_stats")`/`node_count` 缺失 → 新区块不渲染；
  `cooccurrence_plan` 对旧边表（无 node_count）退化为按 PMI 边权估计节点大小，
  不报错。

### 漏洞 5：三端降级不一致
- **对策**：降级判定收敛到 `cooccurrence_plan` 一个 helper，HTML/Word/App
  只消费其返回值，避免各自写阈值。

### 漏洞 6：解读与图表数字不一致（规则取数错位）
- **对策**：解读只读 `narrative_stats` 同一数据源；桶排序、ref 标记、风险热点
  判定全部由 stats 字段派生，禁止渲染层二次重算。

### 漏洞 7：范围外改动
- 不改叙事/归因 LLM prompt（现有 5 框架 × 8 归因词表不变）；
- 不改 Excel 逐条明细（已有两列）；
- 不新增任何 LLM 调用；不重新采集；不新增渠道。

### 漏洞 8：`build_cooccurrence` 签名破坏兼容
- 默认签名/返回值保持不变，新增可选参数 `return_counts`；
  tests/test_tokenizer.py 现有调用零改动。

### 漏洞 9：解读结论与图表口径漂移
- 解读只读 `narrative_stats` 同一数据源（同 §漏洞 6）；
  "问题归因"措辞仅在 `negative_rate≥50%` 时使用，否则退化为事实描述。
