## 二、失败模式（每子集典型样本 + 病历）

### irony（反讽，错误率最高）
1. **短句反讽被当正面**（neutral→positive）：“好厉害”“笑死我了”“多少？太厉害了”“厉害啊好手气”——表面褒义短句，无明确语境，gold 为 neutral（意图不明），模型默认正面。
2. **真负面反讽被当正面**（negative→positive）：“西村力我保证你是史，是世界对你太好了”“笑死了 连在一起了🤣 #喜茶新品”——“世界对你太好了/笑死”被当开心，实际是讽刺/吐槽产品。
3. **抱怨被当中性**（negative→neutral）：“我也是 我也还没解决我问客服了”“绝了，咋还有这么多呢”——负面体验陈述语气平淡，被判 neutral。
4. **“笑死”类正面内容被当负面**（positive→negative）：“笑死人不偿命系列-笑死在评论区”（搞笑视频标题）——把“笑死”一律当嘲讽。

### long（长文本，聚合错位）
1. **攻略/教程/解析被判负面**（neutral→negative）：“氪金攻略之浅算一下活动礼包性价比”“《恋与深空》男主人气大揭秘”——出现“氪金/付费/解析”等词即判负面，实为无观点攻略。
2. **攻略带轻微推荐语被判正面**（neutral→positive）：“网易我的世界活动奖励五选一……这期视频就看看这五个模组试完之后哪个最好”——“一键三连/最好”等词带偏。
3. **同人/剧情片段局部情绪被判整条负面**（neutral→negative）：夏以昼同人剧本（剧情冲突但无产品评价）、饭圈争议分析长文。
4. **长文真负面被局部正面词带偏**（negative→positive）：“他们应该尊重自己过去的设计……各种体型和五官特征的角色都有各自的粉丝”（批评设计丧失独特性）。
5. **官方宣传被判中性**（positive→neutral）：小象超市 App Store 介绍（“一站购齐，最快30分钟送达”）。

### lowconf（词典拿不准，混合后仍 22%）
1. **中立介绍被判正面**（neutral→positive）：“恋与深空男主人气排名”（“情感张力”“冠军”等词）、“守望先锋N卡实测”。
2. **官方正面宣传被判中性**（positive→neutral）：华润万家年货市集央广网报道、瑞幸品牌介绍（“让每一位顾客轻松享受”）。
3. **隐晦/道歉类被判负面**（neutral→negative）：“对不起我之前讲的话有歧义”。

### emoji
1. **嘲讽 emoji 被当开心**（negative→positive）：“笑死我了，被封了吧🤣👉🤡”。
2. **纯表情/无观点被判情感**（neutral→positive/negative）：“能忍住不冲的是这个👍🏻😋”“大家要小心这样的乐子😂😂”。
3. **带 emoji 的正面内容被判中性/负面**：“回购了N次的牛肉干❗️”。

### dialect / jargon（样本少，参考级）
1. 方言正面词被当中性/正面误判：“巴适得很 大哥点评：总体还行”（positive→neutral）；“【深美·冇得顶】……团购页”（neutral→positive，店名含方言词无观点）。
2. 黑话负面被当正面/中性：“搞什么啊顺丰‼️这么低级的错误都会犯😡……好无语啊”（negative→positive）；“还记得当初退坑lysk是因为”（negative→neutral）。

## 三、Prompt v2 修改提案（只加有证据的规则）

目标：修复以上 6 类失败模式，**不改变输出 JSON schema**，token 增量控制在 ~250 以内/请求
（新增规则为紧凑要点，不展开长样例）。当前提示词位于
`app/coding/llm_analyzer.py::_request_batch`，建议在现有"反讽/官方公告"两条注意后追加：

1. **短句反讽不默认正面**：`好厉害/太厉害了/笑死/绝了/真的会谢/谢谢您嘞/真棒` 等表面褒义
   短句，若无法从上下文确定真实褒贬 → **neutral**（意图不明按规范判例 3）；能明确看出
   嘲讽对象/抱怨 → negative。
2. **“笑死/笑死我”按语境二分**：嘲讽/吐槽语境（被封、被坑、翻车、连在一起了）→ negative；
   纯搞笑/娱乐内容标题 → 无观点 neutral；不要一律当嘲讽或一律当开心。
3. **长文先定“作者对游戏/品牌/产品的整体态度”**：攻略/教程/科普/解析/排名/新闻类多为
   无个人褒贬 → neutral；**同人创作、剧情片段、饭圈/争议分析中的局部情绪不算对产品的
   负面**；不要被“氪金/付费/贵/冲突/开盒”等词直接带偏。
4. **官方宣传与中立介绍区分**：官方公告/宣发/更新说明 → neutral（维持）；但**品牌官方
   宣传文案/官方报道/品牌介绍**（含“让顾客享受/一站购齐/最优体验”等正面承诺）→ 按
   positive 判；中立第三方介绍/排名/实测 → neutral。
5. **emoji 不单独构成情感依据**：结合文字语境；`😡😤🤮👊` 愤怒类与 `🤣👉🤡` 嘲讽类可
   强化 negative；纯 emoji/无观点短文本 → neutral。
6. **高频黑话/方言小词表**（仅加最影响判定的一组，不展开词海）：
   - 负面：退坑（不再玩）、翻车（出事）、割韭菜（圈钱）、无语/好无语、低级错误=批评、
     孝钱（讽刺性消费）；
   - 正面：yyds、顶、好正/好鬼正/咁正/冇得顶/巴适/安逸/要得（方言“非常好/满意”）；
   - 注意：方言词若只出现在店名/标题且无观点 → neutral。

**预期**：主要修复 irony（-8~-10 条错误）、long（-6~-8 条）、emoji/lowconf 部分；
方言/黑话小样本仅看方向。不承诺具体 pp（小样本噪声），以连续 2 轮对比为准。
**回退保障**：主集回归硬门槛 + 边界集 vs 上轮对比；每轮记录 prompt 版本与 token 用量。

## 四、实施清单（用户确认后执行）

1. ✅ `llm_analyzer.py`：`_request_batch` system 提示词已追加第 1~6 条规则；
   `PROMPT_VERSION = 2` 常量已加，混合跑分报告带 `prompt_version` 字段；
   主集回归 21/21 全绿 + 词典门槛 PASS（prompt 改动不影响词典链路）。
2. ⏳ `--edge --llm` 对比上轮（77.73%，prompt v1）与冻结基线；
3. 若 irony/long 未提升：回到错误样本复核（本轮错误集存档），再收敛规则；
4. 每轮记录：prompt 版本、准确率、按子集 Δpp、token 用量（防提示词膨胀）。

## 五、第 1 轮复盘（prompt v2，2026-08-13）

**结果**：整体 77.73% → **76.36%（-1.37pp，回退）**；irony 67.3% → **57.1%（-10.2pp）**、
long 70.7% → 68.3%（-2.4pp）；emoji 76.9% → 84.6%（+7.7pp ✅）、lowconf 78.0% → 80.5%
（+2.4pp ✅）、dialect/jargon 持平。错误集 diff：修复 17 / 回退 20 / 两轮都错 32。
Token：prompt tokens 21607 → 29188（+35%）。

**根因**：v2 规则"矫枉过正"——把真情感也压成 neutral：
1. 规则 2"纯搞笑/娱乐内容标题判 neutral"与 gold 冲突：粉丝/娱乐语境"笑死😂"
   （"真要被周佑凌笑死！""她野太好玩了各位，笑死😂"）gold 为 **positive**，
   12 条 irony 回退中 10 条是 positive→neutral；
2. 规则 1 把明显夸赞（"我宝宝好厉害又接到未开售的推广了"）误判为反讽 negative；
3. 规则 3 的"新闻→neutral"误伤按内容有明确情感的报道（瑞幸联名卖爆→positive、
   星巴克胭脂虫→negative 被判 neutral）；
4. 规则 4 的"品牌介绍→positive"误伤公司官网/介绍页（大疆官网使命陈述、职友集、
   世界之外精华帖，gold 为 neutral）。

**修订（prompt v2.1，`PROMPT_VERSION = 3`）**：
1. 短句信号词三分：明显夸赞→positive / 明显嘲讽→negative / 无法判断→neutral；
2. "笑死"按语境：娱乐/粉丝/搞笑→**positive**；嘲讽/吐槽→negative；无观点标题→neutral；
3. 新闻/报道**按实际内容情感判**（负面事件→negative、热销→positive），攻略/教程/解析
   才默认 neutral；保留"同人局部情绪不算产品负面"；
4. 官方内容分层：官方公告→neutral；**面向消费者的营销宣传→positive**；
   **公司/品牌介绍页与使命陈述、官网导航→neutral**；
5. emoji 规则保留（emoji/lowconf 已受益）；
6. 词表规则保留（jargon/dialect 未回退）。

**待验证**：用户侧重跑 `--edge --llm`（prompt v2.1）对比 76.36%；目标 irony 回到
≥67.3%（v1 水平）以上、long ≥70.7%、emoji/lowconf 维持提升、整体 ≥77.7%。

**整体 80.91%**（v1 77.73% → +3.18pp；v2 76.36% → +4.55pp）。全部子集 ≥ v1：

**结论**：v2.1 为当前最优版本，规则修正方向正确（v2 的"一律→neutral"是反面教材）。
剩余 irony/long 为最难样本（真负面反讽、平淡抱怨、攻略误判），继续堆规则收益递减；
下一步：① 同版本复跑确认稳定性（连续 2 轮口径）；② 若稳定，进入低置信分桶校准与
