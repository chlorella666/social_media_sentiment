## 〇、背景与目标

### 大白话

现在采集清洗是一条流水线：先"认得出"（正则/黑名单/别名）→"拉得齐"（归一化）→"找得到关系"（容错匹配）→"洗得净"（清洗/脱敏）→"查得出重"（去重）→"管得住账"（丢弃明细）。结构性问题有三个：

1. 归一化放在识别**之后**——样板/壳正则直接匹配原始文本，大小写/全半角变体易漏；
2. 丢弃没有旁路记账——中间每一步丢了什么、为什么丢，没有痕迹，这正是历史"丢弃率高但内容其实相关"排查困境的根源；
3. 脱敏只覆盖 LLM 边界——**导出链路（result.json / Excel / HTML）存的是未脱敏原文**，导出物含 PII 风险。

> v0.2 修正：原 v0.1 误写"噪音清洗与 PII 脱敏混为一步"——实际代码 `clean_text`（噪音清洗）与 `desensitize_text`（PII 打码）是独立函数，清洗链里没有混用；脱敏仅在 LLM 发送前与演示脚本执行。真实缺口是导出边界未脱敏。

### 目标（验收口径）

- ① 样板/壳正则前置轻归一化后，命中率不降反升；
- ② 任意被丢弃数据可按「步骤 + 原因」回溯原文（指纹 + 记账）；
- ③ 低置信条目打标后并入 `review_enabled` 人工筛选（一次停下处理全部），而非直接判「不相关」；仅用户显式开启复核时才分流；
- ④ 导出物（Excel/HTML）的"文本内容"列统一 PII 打码，报告正文保留原文；
- ⑤ 全量回归 38/38 + 黄金集 PASS（黄金集不经过清洗链，仅作全局门禁）；
- ⑥ 账目核对通过：清洗层 `clean_posts 入参 = 保留 + 清洗丢弃（分步骤/原因）+ 去重丢弃`；采集层跳过由 `collection_stats` 单独核对。

## 二、目标流水线（9 步，v0.3 口径）

```
渠道返回（原始）
  → 采集层跳过记账（collection_stats：风控/上限/重复 URL，独立核对）
  → 1 开账：清洗层入参记 ID + 原文指纹（哈希），任何一步丢弃可回溯
  → 2 轻归一化：大小写折叠 / 全半角折叠 / 空白标点压缩（供样板/壳正则使用）
  → 3 噪音清洗：高置信纯噪音（哈哈哈/2333/@提及）先删
  → 4 认得出：样板/壳 / 官方页判定（文本已规整）
  → 5 找得到关系：容错匹配（_relevance_match 返回 (score, reason)）
  → 6 置信度分流：低置信打标 → 并入 review_enabled 筛选页（一次停下；≤50 全进、>50 按分低到高取 50）
  → 7 查得出重：清洗后文本精确/近似去重，保留最完整一条，重复来源记账
  → 8 脱敏：导出物（Excel/HTML）文本内容列统一 PII 打码，报告正文保留原文
  → 9 关账核对：清洗层入参 = 保留 + 清洗丢弃(步骤/原因) + 去重丢弃；采集层跳过单列
```

## 三、分阶段实施方案（每阶段独立提交 + 独立验证）

### 阶段 0：建基线（必做，不跳过）

- 产出：`test_cleaner.py` 增补基线用例（并入现有文件，保持 38/38）+ 从日志/快照重建的可复现 fixture（D8）；
- 改动：仅测试，不碰 `cleaner.py` 逻辑；
- 验证：基线全绿 + 真实数据词典准确率对比记录 + 黄金集 PASS。

### 阶段 1：开账（最低风险，先做）

- 改动：`clean_posts` 入口为每条入参生成 `fingerprint`（清洗前原文哈希）；`dropped` 扩展 `{step, fingerprint, content}`；
- 行为：不改判定逻辑，只加账本；
- 验证：基线行为等价 + 丢弃记录含 step/fingerprint。

### 阶段 2：样板/壳正则前置轻归一化

- 改动：新增 `_light_normalize(text)`（大小写/全半角/空白标点压缩），仅用于 `is_boilerplate`/`is_official_page` 前；`_relevance_match` 不动；
- 注意：`_light_normalize` 压缩空白改变 F-031 `SHELL_COMBINED_RE` 匹配范围——接受变化，壳残留抽查零残留（D5）；
- 联动：噪音提前删 → content_texts 变化 → F-033 共现/词云/话题簇回归；
- 验证：基线 + 真实数据词典准确率对比 + test_cleaner + test_report_insights（共现/话题簇）+ 黄金集。

### 阶段 3：置信度分流（独立下一轮，D1/D2 已定稿）

> 本轮不执行（D3 定稿：阶段 3 独立下一轮）。以下为下一轮实施规格。

- **D2 连续分数**：`_relevance_match` 返回 `(score, reason)`——整词包含=1.0、别名=0.9、相似=覆盖率（`lcs_len ÷ 信号词长度`）、未命中=0.0；**`clean_posts` 内 `if not match_hit:` 同步改为 `if match_hit[0] <= 0:`（元组恒真陷阱，必改）**；`dropped["match"]` 落盘存 `reason`；阈值 0.6（相似且覆盖率 <0.6 进桶，看实测量再调）；
- **D1 并入 review_enabled 一次停下**：低置信打标 `platform_specific["low_confidence"]=True`，随采集快照并入现有 `review_enabled` 筛选页；≤50 条全进、>50 条按分低到高取 50；仅显式开启时生效；不新增第二次暂停；
- 改动：`cleaner.py`（分数化 + 打标）、`jobs.py`（快照字段）、`results.py`（筛选页低置信标记/过滤）、`test_cleaner.py`（分数与消费断言）；
- 联动：F-007 need_review 不受影响（编码后独立）；`test_review.py`/`test_ui_flow.py` 复核流程回归；
- 验证：基线 + 黄金集 + 待复核桶持久化测试 + 复核流程回归 + 实测量复核（桶容量/阈值评估）。

### 阶段 4：去重统一 + 导出脱敏

- 去重：确认 `dedupe_posts` 调用方；`clean_posts` 内联为事实标准，`dedupe_posts` 无调用方则删除；
- 脱敏（D4）：导出物（Excel/HTML）的"文本内容"列统一调用 `desensitize_text`；**报告正文（report_text/结论区）保留原文**；PII 残留扫描 0（文本内容列）；
- 验证：基线（保留条数）+ 导出物文本列 PII 扫描 0 + test_cleaner。

### 阶段 5：关账核对

- 改动：清洗链末尾断言 `清洗层入参 = 保留 + 清洗丢弃(step 明细) + 去重丢弃`；不平衡**先抛错**（账目红线，D6），实测误报多再降级 warning；采集层跳过由 collection_stats 单独核对；
- 验证：账目平衡测试 + 全量回归。
