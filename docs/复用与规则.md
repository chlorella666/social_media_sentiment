## 1. 总体架构与数据流

```mermaid
flowchart LR
    UI[Streamlit 向导/结果/任务中心] -->|AnalysisPlan| DB[(SQLite data/app.db)]
    DB --> WORKER[常驻 worker app/worker.py]
    WORKER --> CH[渠道适配器 channels/]
    CH --> CL[清洗 cleaner.py]
    CL --> COD[编码 coder.py: 词典+LLM]
    COD --> INS[洞察与证据 evidence/insights]
    INS --> OUT[输出 Excel/HTML/Word/JSON]
```

分层职责（详见 [技术方案.md](技术方案.md)）：

| 层 | 位置 | 职责 |
|---|---|---|
| 前端 | `app/main.py` + `app/ui/` | 6 步向导、任务中心、结果渲染、大模型设置 |
| 后台 | `app/worker.py` | 常驻进程：轮询任务、执行管道、心跳、崩溃恢复 |
| 任务库 | `data/app.db`（SQLite） | 任务/进度/日志/渠道配额/风控状态 |
| 管道 | `app/core/pipeline.py` | 采集→清洗→编码→汇总→报告的完整编排 |
| 渠道 | `app/channels/` | 注册表模式，每个平台一个适配器 |
| 评测 | `app/eval_dashboard.py` + `tests/benchmark_golden.py` | 黄金集/边界集跑分、基线门槛、趋势 |

**数据流关键约定**：
- 全链路统一 Pydantic 模型（`AnalysisPlan / Post / ChannelResult / CodedItem / ReportBundle`），渠道、编码、输出互不感知对方内部结构；
- `summary` 是图表 / Excel / HTML / Word 共用的唯一统计口径，各输出端不得自行重算；
- `result.json` 是完整结果落盘（含 plan/channel_results/summary/evidence/warnings），供历史回看与二次开发。

## 2. 核心框架（可复用骨架）

### 2.1 任务管道 TaskRunner（`app/core/pipeline.py`）

一次分析被拆成**两段、四阶段**，阶段权重与状态机固定：

| 阶段 | 权重区间 | 说明 |
|---|---|---|
| collecting 采集 | 0.00–0.50 | 各渠道并发/串行采集，风控即停保留已采部分 |
| cleaning 清洗 | 0.50–0.60 | 清洗去重 → LLM 相关性复核（可选）→ 补采（最多 2 轮）→ 一致性收尾 |
| coding 编码 | 0.60–0.90 | 词典预筛 → 低置信送 LLM → 维度级情感 →（可选）叙事/归因 |
| reporting 报告 | 0.90–1.00 | summary 重算 → 证据链 → findings → 报告文本 → 落盘 |

可复用的机制：
- `collect_and_clean()` / `code_and_report()` 两段拆分：**人工筛选后可从编码段续跑**，无需重采；
- `ProgressTracker` + `ProgressCallback`：阶段进度单调不回退、1 秒节流写库；
- 零数据短路：`summary["total_items"] == 0` 时不调 LLM、不生成任何推断，走 `NO_DATA_REPORT_TEXT`；
- 取消为尽力而为：采集阶段立即停，其余阶段跑完当前批次后不落输出；
- 重跑 = 用原计划新建任务（重新进入 pending），不是状态迁移。

### 2.2 渠道适配器框架（`app/channels/`）

**注册表模式**：新增平台 = 继承 `ChannelAdapter` + 注册一行。

```python
class ChannelAdapter(ABC):
    id / name / auth_required / applicability / description / demo / skip_key
    def collect(plan, on_progress=None, cancel_event=None, skip_urls=None) -> ChannelResult
```

- 统一返回 `ChannelResult(channel_id, ok, posts, dropped, collection_stats, warnings, error, degraded, risk)`；
- 单渠道失败自动降级（`degraded_result()`），不影响整体流程；
- `collection_stats` 是采集透明度统计（API 返回/跳过/保留），报告「采集说明」直接消费；
- `skip_key`（url 或 id）决定补采时按什么键跳过已采内容；
- `jittered_sleep(base, ratio)`：均值抖动休眠，防固定节奏被识别为机器行为，所有渠道复用；
- 现有注册表（`registry.py`，按优先级排序）：demo → bilibili → websearch（含 zhihu/tieba/taptap 子渠道）→ weibo → xiaohongshu。

### 2.3 领域维度体系（`app/domains/` + `app/coding/dimensions.py`）

三层结构，可独立扩展：

1. **预置领域 JSON**（`app/domains/*.json`）：完整 `DomainSchema`，如 `digital3c`；
2. **模块模板库**（`app/domains/domain_templates.json`）：content（数字产品）/ physical（有形实物）/ service（服务内容）三模板，组合生成 `modules_<ids>` schema，合并规则见 §4.9；
3. **自定义维度**：任务级 `custom_dimensions`（`custom_` 前缀防冲突，≤4 个），`task_schema(plan)` 负责把预置/模块 + 自定义合并成最终分析 schema。

关键约定：
- 组合维度**强制 ≤10**（超出由向导引导取消勾选）；
- 组合 schema 物化落盘到 `data/domain_schemas/`，worker 直接按 `domain_id` 加载，无需改计划模型；
- `template_fingerprint`（模板文件 sha256 前 16 位）是模块缓存失效依据，模板改动后旧缓存自动失效重合成；
- 新领域经提案引擎（`proposer.py`）生成候选 → **人工确认表是硬门槛** → `apply` 落库；
- 维度级情感：词典侧用 `match_dimension_sentiments`（分句打分，冲突不标），LLM 侧为 2.4 主口径。

### 2.4 后台任务队列（`app/core/jobs.py` + `app/worker.py`）

可复用机制：
- 原子抢单（`claim_next_task`：pending→running）、心跳（任务级 10s / worker 级 10s）、
  崩溃恢复（`recover_stale_tasks`：心跳超时 90s 的 running 标记 failed，可重跑不自动重试）；
- 渠道配额：`check_channel_allowed`（预检）→ `consume_quota`（预扣）→ `settle_quota`（回填/退款）；
- 风控冷却：`set_cooldown` 指数退避 `10min × 2^level`，封顶 60min；
- 手动暂停/恢复、每日配额（weibo 200 / xiaohongshu 100）；
- 取消请求 `request_cancel` 与渠道层 `cancel_event` 联动；
- 任务日志双写：SQLite（UI 错误视图）+ JSONL（`data/logs/app.jsonl`），全部 best-effort。

### 2.5 评测体系（`tests/benchmark_golden.py` + `app/core/eval_store.py`）

可复用资产：
- **黄金集**（`tests/fixtures/golden_set_v1.csv`，脱敏入库版）与**边界集**（`edge_set_v1.csv`）：词典直判基线 + 混合（词典+LLM）两种模式；
- **冻结基线**：`tests/fixtures/baseline_lexicon.json`（词典，硬门槛）/ `baseline_hybrid.json`（混合，仅记录）/ `baseline_edge_*.json`；
- **指标**：整体准确率、分组准确率（渠道/领域/情感类别/语言现象）、情感类别 P/R/F1（负面向召回是核心）、维度级微平均 P/R/F1 + 精确命中率；
- **统计严谨性**：95% Wilson CI（z=1.96）、Δ 判定宽度 = √(ci₁²+ci₂²)、两侧 n≥30 且 Δ 在 CI 内判「噪声内」；
- **指纹守卫**：golden 文件指纹、领域 schema 版本号变更 → 基线重冻结；
- **hold-out 纪律**（`tests/coldstart_annotation.py` + `test_validation_discipline.py`）：分层切分（渠道/品牌配额 + 时间窗三分桶）、冻结只读、使用次数 ≤2、`--force` 重切清零、`--exclude-gold-revised-by-model` 过滤参考过模型的 gold。

### 2.6 前端 UI 分层（`app/ui/`）

`main.py` 按页拆出共享模块，新页面直接复用：
- `constants.py`：渠道默认/封顶上限、步骤定义、SVG 状态图标、广告复核模式、API Key 指引；
- `theme.py` / `global.css`：设计令牌（色板、字体、圆角），与 `design_entries/ui-designer/design_tokens.css` 同源；
- `terms.py`：术语「人话层」tooltip 文案池（新指标先补文案再上线）；
- `sidebar.py` / `wizard.py` / `tasks.py` / `results.py` / `dev.py`：向导、任务中心、结果页、开发者工具。

## 4. 规则体系速查

### 4.1 清洗规则（`cleaner.py`）

| 规则 | 值/行为 |
|---|---|
| 四重去重键 | ID / URL / 标题前 50 字 / 正文前 50 字 |
| 正文去重键生效条件 | 长度 ≥20 且 ≠ 标题（避免 B 站空正文/短简介误杀） |
| 过短判定 | WebSearch 渠道 <5 字，其他 <10 字 |
| 样板/页面壳 | 预置正则（加载中/扫码下载/属地等） |
| 官方页面 | 标题含「官网/首页/官方…」，但含「评价/评论/评分」等聚合页特征时不算 |
| 相关性 | 归一化整词包含 → 品牌别名（`BRAND_ALIASES`）→ 最长公共子串前缀（中文≥2 / 字母≥3） |
| 弱相关保留 | 有实质正文但未命中：保留并标 `relevance=weak`，交 LLM/人工，不硬杀 |
| 丢弃 kind | `collection`（采集层跳过，补采豁免）/ `duplicate`（去重，补采豁免）/ `quality`（计入决策） |
| 脱敏范围 | @用户名、链接、邮箱、11 位手机号、18 位身份证；**不删任意短数字串**（防误伤模组码/订单号） |

### 4.2 词典编码规则（`lexicon_v2.py`）

| 规则 | 值/行为 |
|---|---|
| 词典组成 | 精选网络词（`_CURATED_WORDS`）+ ECSD 电商词（多字）+（可开关）cnsenti 知网词 |
| 单字词 | 只保留精选低碰撞表（牛/爽/甜/香/稳/准 + 坏/丑/烦/破/疼/漏/裂/渣/碎/臭/慢/脏/吵） |
| 评分算法 | 程度副词窗口 + 否定翻转 + tanh 归一化（`THRESHOLD_POS=0.15` / `THRESHOLD_NEG=-0.15`） |
| 负面强化词 | 触发即强扣（塌房/翻车/暴雷/智商税/割韭菜/逼氪/欺诈/事故） |
| 语境词 | 无固定极性，评分前掩码排除（差异/一般/还行/相比/一样等） |
| 中性语体防直判 | 命中官方/教程/攻略/实测/参数等标记且仅正面信号 → 压置信送 LLM |
| 展示置信度 | 词典直判封顶 0.6（校准 spike 结论：词典高置信不可信），LLM 原样 |
| 置信分档 | 高 ≥0.8 / 中 ≥0.5 / 低 <0.5 |

### 4.3 LLM 编码规则（`llm_analyzer.py` + `coder.py`）

| 规则 | 值/行为 |
|---|---|
| 触发条件 | 词典置信 <0.8（`CONFIDENCE_THRESHOLD`）或 开启 LLM / 自定义维度 / 强制领域 |
| 强制 LLM 领域 | digital3c / game / consumer / 所有 `modules_*` |
| 送 subject 的领域 | digital3c（`SUBJECT_DOMAINS`） |
| 批量 | 精分析批 10 条、并发 4 批；叙事批 6 条 |
| 发送前 | 一律 `desensitize_text`（三入口：精分析/叙事/相关性复核） |
| 防御 | 模型返回非法情感值（如 mixed）→ 保留词典结果；叙事异常不中断主流程 |
| 修正记录 | `lexicon_sentiment` 保留词典判定，`llm_corrected` 统计修正数 |

### 4.4 需复核规则（`coder.py`，v3 默认，`SMS_NEED_REVIEW_RULE` 可切 v1/v2）

| 信号 | 说明 |
|---|---|
| 词典直判 | v3 全领域必标「词典直判(未送LLM)」 |
| 低置信 | conf <0.7（v2/v3；v1 为 <0.5） |
| 反讽/方向不明 | 命中 `IRONY_MARKERS` |
| 黑话/圈内语 | 命中 `SLANG_MARKERS`（挤牙膏/智商税/真香/翻车 等） |
| 问句/短句 | **仅 digital3c 生效**（校准 spike：其他领域只增负担不加召回） |

### 4.5 广告/官方规则（`ad_rules.py`）

- 默认**计入统计**（广告是市场信号）；`exclude_ad_enabled=True` 时仅从情感统计剔除，漏斗/关键词效果保留并注明；
- 规则预标 + 人工复核回填；识别 = 官方标题特征 或 营销信号词表（`AD_MARKERS`，保守词表防误伤）；
- 三种广告复核模式见 `app/ui/constants.py: AD_REVIEW_MODES`。

### 4.6 补采规则（`pipeline.py`）

| 参数 | 值 |
|---|---|
| 触发条件 | quality 类丢弃率 >15% 且 保留数 < target（demo 不补采） |
| 轮数上限 | 2（`TOPUP_MAX_ROUNDS`） |
| 数量乘数 | target/0.85，封顶 limit×2（`TOPUP_LIMIT_MULTIPLIER`） |
| 收益门槛 | 净新增 ≥ max(3, target×0.2)（`TOPUP_MIN_YIELD` / `TOPUP_YIELD_RATIO`） |
| 跳过条件 | 冷却/暂停/超配额渠道跳过；小红书高风险先提示 |
| 一致性收尾 | 补采帖最终再清洗一次统一写回，避免「报告 0 帖但漏斗有数」 |

### 4.7 数据质量门控（`pipeline.py: _quality_gate_warnings`）

样本量逐级降级提示：0（无数据）/ <10（仅供参考）/ <30（趋势对比置信度有限）/ <45（平台对比仅供参考）/ <100（建议扩大采集）。

### 4.8 消费者声音分档（`pipeline.py`）

- E = 保留且非广告/官方文本；占比 = E / 采集量；
- 分档：E ≥ 0.6×目标 且 正/负都 ≥ 最小条数 →「充足」；E ≥ 0.3×目标 且 负 ≥ 最小 →「够用」；否则「不足」；
- 正/负最小条数默认 10%×E，bilibili / demo 降为 5%×E（视频标题语体天然低正负占比，防误报）。

### 4.9 领域组合合并规则（`domains/composer.py`）

| 合并目标 | 源维度 | 保留后名称 |
|---|---|---|
| price_value | content.monetization / physical.price_value / service.price | 价格价值 |
| brand_image | physical.brand_image / service.brand_trust | 品牌与营销 |
| channel_service | physical.channel_service / service.after_sales | 渠道与售后 |
| effectiveness | content.performance / physical.effectiveness | 功能与稳定性 |

组合时取并集、按概念去重、吸收后出现的 keywords；组合维度 ≤10。

### 4.10 证据与发现规则（`evidence.py`）

- 证据卡：原文卡（维度级 → 话题反查 → 整体负面 TOP）+ 统计卡；id 前缀 E / S，稳定排序；
- 原文截断 80 字；findings 上限 5 条；
- 样本守卫：维度 n≥10 正常评级、3–9 标「样本有限」、<3 不评级；叙事/归因桶 count<10 标「样本有限」；
- 措辞纪律：负面率 ≥50% 说「负面集中」，<50% 说「涉及」；词典模式加「疑似」前缀；
- 零数据不生成任何 findings；负面占比高于正面时绝不允许「中性/正面为主」表述；
- LLM findings 必须逐条通过校验（引用真实证据 id），校验不过整组丢弃降级为规则 findings。

### 4.11 渠道配额与风控

**每关键词条数上限（UI 默认 / 封顶）**：

| 渠道 | 默认 | 封顶 |
|---|---:|---:|
| demo | 10 | 200（确定性数据，限额不影响产量） |
| bilibili | 10 | 50 |
| websearch（含子渠道） | 13 | 13 |
| weibo | 10 | 30 |
| xiaohongshu | 10 | 10 |

> 加量原则：**增加关键词而不是调大上限**（README/UI 帮助同口径）。

**风控与配额**：

| 机制 | 规则 |
|---|---|
| 每日配额 | weibo 200 / xiaohongshu 100（预扣 + 回填/退款） |
| 冷却退避 | 10min × 2^level，封顶 60min；可一键解除 |
| WebSearch 引擎池 | 360 → cn.bing → 夸克；验证码等硬风控「验证码即停」不再请求后续引擎 |
| WebSearch 节流 | 请求间隔 4.5s ±25% 抖动；空结果重试 1 次（等 10–20s）；连续 2 个关键词空结果判定风控 |
| WebSearch 每日上限 | 关键词总量 24（含子渠道展开） |
| 渠道失败 | 自动降级保留其他渠道；风控即停保留已采部分并触发冷却 |

### 4.12 评测门槛与验证纪律

| 规则 | 值/行为 |
|---|---|
| 词典基线门槛 | accuracy ≥ 基线 − 1.0pp（`DEFAULT_TOLERANCE_PP`），跌破 FAIL，需 `--accept-baseline` 显式接受新基线 |
| 混合/边界集 | 仅记录不设硬门槛（边界集为「strict-edge A 档」提示 + 人工验收） |
| 单元测试 | 失败自动重跑 1 次降 flaky 假红（`--no-retry` 关闭） |
| CI | windows + ubuntu 双平台，`--ci` 禁验收 / 禁 LLM / 禁写 docs |
| 提准四道关 | 新样本 / 干净裁判 / 噪声感知 / 跨领域 |
| hold-out 纪律 | 分层切分（渠道/品牌配额 + 时间窗三分桶）、冻结只读、使用 ≤2 次、判定需超 95% CI |
| gold 修订 | 参考过模型判定的行必须可过滤（`gold_revised_by_model`），盲审档验收 |

### 4.13 数据生命周期（`lifecycle.py`）

| 规则 | 值/行为 |
|---|---|
| 自动归档（可逆） | 不在最近 30 个 且 超 7 天 且 终态 且 无人工筛选快照 → 移入 archive |
| 显式清理 | 归档超 90 天、日志超 30 天、旧回归报告；优先回收站（send2trash） |
| 永不自动触碰 | `data/secrets/`（API Key/Cookie）、`data/state/`（确认记录）、任务/配额库 |
| worker 磁盘预检 | 低于 `DISK_MIN_FREE_MB` 阻止新任务 |
| 进程互斥 | LifecycleLock（锁 10 分钟过期回收） |

### 4.14 关键词策略（`app/channels/keyword_strategy.json`）

- schema v2：`synonyms / extra_queries / suffix_pool` 仅 WebSearch；`rules.<channel>` 为渠道级查询策略；
- 约束：bilibili/weibo 每品牌查询 ≤5；小红书 `preferred` ≤2（只精简不扩量）+ `avoid` 低效词；
- 更新路径：`python app/core/keyword_effects.py --scan-dir data/reports --candidates` 反推候选 → 人工确认 → 写回 JSON，下次采集生效。

### 4.15 费用估算（`pricing.py`）

DeepSeek 示例单价：输入 ¥2/百万 token、输出 ¥8/百万 token；约 70% 文本送 LLM（阈值 0.8 实测）；平均 60 字/条、0.7 token/字。常量可手动更新，实际以接口 usage 为准。

## 5. 扩展指南（怎么复用）

### 新增一个渠道
1. 继承 `app/channels/base.py: ChannelAdapter`，实现 `collect()`，返回 `ChannelResult`；
2. 遵守节流/风控约定：`jittered_sleep` + `is_ratelimit` + `set_cooldown`；风控即停置 `risk=True`；
3. 在 `registry.py` 注册并加入 `list_channel_infos()` 优先级表；
4. 在 `app/ui/constants.py` 补 `CHANNEL_LIMIT_DEFAULTS / CHANNEL_LIMIT_MAX / CHANNEL_LIMIT_HELP`；
5. 补 `collection_stats` 统计（采集透明度），跑 `test_contracts.py` 契约校验；
6. 按 [渠道验收矩阵](渠道验收矩阵.md) 标准做真实验收。

### 新增一个领域 / 维度
1. 用 `app/domains/proposer.py` 生成提案（模板建议 + 证据候选）；
2. **人工确认表确认后** `apply` 落库 `data/domain_schemas/`；
3. 领域 schema 版本号变更会触发评测基线重冻结（指纹守卫）；
4. 纯模块化分类（content/physical/service）无需建领域，向导组合即可。

### 新增一个规则 / 阈值
1. 优先放进现有模块（cleaner / lexicon_v2 / evidence / pipeline），常量集中定义并注释决策日期；
2. 若影响判定质量：过「四道关」验证纪律，跑 `python tests/run_regression.py`（词典门槛）确认不破基线；
3. 报告展示相关：同步更新 `app/core/terms.py` 术语 tooltip；
4. 规则可开关时用环境变量 + 默认值（如 `SMS_NEED_REVIEW_RULE`），并保留旧规则回退路径。

### 新增报告输出端
1. 只消费 `ReportBundle`（尤其 `summary`），**不得自行重算统计**；
2. 复用 `app/output/` 现有写入器风格，图表描述用 `chart_insights`；
3. 落盘路径与 `update_task_files` / 归档逻辑保持一致。
