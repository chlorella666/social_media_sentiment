# 社交媒体情感分析器 — 项目方案与技术规格

> 版本：v0.4.0 | 最后更新：2026-08-04
> 本文档定位：**可复刻规格**——依据本文档可直接重建本程序（代码实现细节与文档一致，含算法公式、数据模型、接口与提示词）。

---

## 一、产品定位

一个**小白可上手的本地 Web 应用**：用户输入品牌/产品名（或直接手输关键词），程序以向导方式逐项确认分析维度、关键词、采集渠道和时间段，随后自动完成 **采集 → 清洗 → 情感编码 → 图表 → 报告** 全流程，输出可下载的原始数据 Excel 与 HTML/Word 分析报告。

核心特性：

1. **领域自适应维度**：预置「游戏」「消费品」两套维度体系，品牌名自动生成关键词建议
2. **多渠道采集**：演示数据 + WebSearch/微博/知乎/B站/小红书适配器（真实渠道 V1 接入）
3. **混合情感编码**：词典规则预筛（快、零成本）→ 低置信度文本调用大模型 API 精分析
4. **深度洞察**：12 张图表各配解析文字 + 按五种叙事框架生成综合结论
5. **进度透明**：可展开的任务清单，每步状态（等待/进行中/完成/跳过/失败）与进度实时可见

### 2026-08-06 LLM 路由阈值 0.5 → 0.8

- 决策：词典预筛置信度低于 **0.8** 的文本全部送 LLM 精分析（更保守，减少词典误判
  直接出结果）。
- 基准（online_shopping_10_cats 抽样 2000 条，LLM 假设准确率 90%）：
  | 指标 | 0.5 阈值 | 0.8 阈值 |
  |------|----------|----------|
  | 送 LLM 文本占比 | 45.1% | **69.5%** |
  | 词典直判占比 | 54.9% | 30.5% |
  | 混合流水线准确率 | 91.6% | 91.6% |
- 影响：约 **七成文本** 进入 LLM 精分析（较 0.5 阈值预筛阶段 LLM 调用量约增 1.5 倍），
  词典直接出结果的文本显著减少、其误判影响随之降低；费用随调用量上升。

### 2026-08-06 本地轻量模型替换预筛：评测结论（不采用）

> 结论：**保持"词典直判 + LLM 兜底"流水线，不引入本地轻量模型替换预筛。**
> 已完整评测三种方案（基础模型 / 领域微调 / 特征融合），供后续决策参考，
> 避免重复实验。

- **评测数据**：公开语料 `online_shopping_10_cats`（6.28 万条，留出 20% 测试）
  训练；真实域外测试用 `验收试跑v4` 三品牌情感编码明细（109 条，正负 85 /
  中性 24，标签来自词典+LLM）；微调额外使用 DeepSeek 伪标注 476 条真实文本
  （`data/models/pseudo_labels.json`）。
- **三方案成绩**（真实域外整体准确率，按 LLM 兜底 90% 假设口径）：
  | 方案 | 训练组成 | 真实域外整体 | 二分类（仅正负） | 直判条数/109 |
  |------|----------|--------------|------------------|--------------|
  | 基础 LR | 仅公开语料 | 76.3% | 60.0% | 51 |
  | 基础 NB | 仅公开语料 | 82.1% | 65.9% | 54 |
  | 微调 NB（W=30） | 公开 + 伪标注真实样本 | 86.8% | 78.6% | 49 |
  | 融合 LR（W=100） | 公开 + 伪标注 + 词典特征 | 84.8% | 76.8% | 50 |
- **公平对比：直判规模-准确率曲线**（同一 v4 真实数据，按置信度从高到低直判
  前 N 条正负样本）：
  | 直判前 N 条 | 词典 V2 | 微调 NB（W=30） | 融合 LR（W=100） |
  |------|----------|-----------------|------------------|
  | N=15 | 100% | 100% | 100% |
  | N=30 | 100% | 93.3% | 95.0% |
  | N=50 | 98.0% | 86.0% | 90.0% |
  | N=70 | 90.0% | 80.0% | 91.4% |
- **不采用的原因**：
  1. 同等直判条数下词典准确率高于模型（前 30 条词典 100%，模型 93~95%），
     模型无法在保持准确率的前提下扩大直判规模；
  2. 词典阈值 0.5 只直判 15 条（100%），模型可直判 50 条（86~90%）——模型
     省 LLM 调用的收益（约 37%）不足以弥补准确率差距（约 10 个百分点）；
  3. 评测标签本身来自"词典+LLM"，词典直判存在自我印证、模型存在伪标注
     同源偏差，真实业务中模型表现预计还会再降；
  4. 提高 LLM 路由阈值（0.5→0.8）已用更低改动成本获得准确率兜底。
- **遗留**：若未来要重新评估，方向是"本地模型只做预筛省费（先直判再路由
  LLM）"，需扩大伪标注规模至数千条并覆盖更多领域，且评测口径改为
  "省调用率 + 混合准确率"双指标，而非替换词典。

## 六、数据模型规格（Pydantic v2）

### AnalysisPlan（采集计划，向导产物）

| 字段 | 类型 | 说明 |
|------|------|------|
| subject | str | 品牌/产品名或主题 |
| domain_id | str? | 领域 id（game/consumer） |
| dimensions | list[str] | 选中维度 id |
| keyword_groups | list[KeywordGroup] | 按维度分组关键词（dimension_id/name/keywords） |
| keywords | list[str] | 平铺关键词（采集用） |
| channels | list[ChannelConfig] | channel_id + params（如 weibo.cookie） |
| date_start/date_end | date? | 时间段 |
| per_keyword_limit | int=50 | 每关键词上限 |
| comments_enabled / comments_per_post | bool=on / int=20 | 评论开关与上限 |
| llm_enabled / narrative_enabled | bool | LLM 精分析 / 叙事归因开关 |

### Post（统一帖子模型）

`id, platform, keyword, author, title, content, url, timestamp, likes, reposts, comments_count, comments[]`，`platform_specific: dict` 存平台特有字段。

评论 `Comment`：`author, text, likes, time, is_reply, reply_to, depth`。

### CodedItem（每条文本编码结果）

`text_id, text, platform, pub_date, dimensions[], sentiment(positive/negative/neutral), intensity(1-5), sentiment_score(-1~1), confidence(0-1), method(lexicon/llm), keywords[], narrative?, attribution?`

### ReportBundle（一次分析完整结果）

`plan, channel_results[], coded_items[], summary(dict), report_text(概览), chart_insights(dict: 12 图解析), conclusion(深度结论), warnings[], created_at`

### summary 结构（build_summary 产出，供图表/报告/Excel 复用）

- `total_items / total_posts / avg_score / overall_sentiment`
- `sentiment_distribution`：positive/negative/neutral 的 count + ratio
- `platforms`：每平台 posts/avg_score/positive/negative/neutral
- `dimensions`：每维度 count/negative/negative_rate/avg_score
- `intensity_distribution`：1~5 级计数
- `platform_dim`：平台 × 维度 {count, negative, negative_rate}
- `date_dim`：日期 × 维度 {count, negative, negative_rate}
- `trend`：日期 {count, avg_score, negative}
- `top_words`（词典情感词 Top20）、`top_content_words`（jieba 内容词 Top50）
- `cooccurrence`：[{source, target, weight}] Top30

## 八、采集计划与关键词生成（app/core/planner.py）

### 关键词生成算法（generate_keyword_groups）

按选定维度生成建议词，每维度 3~4 个：

1. 短词：`{subject} {维度核心词}`（维度 keywords 列表第 1 个）
2. 中词：`{subject} {维度名}`
3. 中长词：`{subject} {第2个核心词} 评价`
4. 长词：`{subject} {第3个核心词} 怎么样`（仅当维度关键词 ≥3）

手动模式直接使用用户输入；自定义维度生成 `{subject} {自定义名}`。

### build_plan

组装 AnalysisPlan；手动关键词非空时以手动为准（KeywordGroup dimension_id="manual"）。

### 领域 schema（JSON）

每个维度含：`id, name, description, source, keywords[], sub_dimensions[]`（二级子维度）。预置两套 7 维度（游戏：角色/剧情/氪金/美术/玩法/运营/Bug；消费品：质量/价格/体验/品牌/渠道/安全/竞品）。loader 优先读 `data/domain_schemas/{id}.json` 缓存，否则读预置 JSON。

## 十、清洗与编码管道

### 清洗（cleaner.py）

步骤化管道（可注册增删）：

1. Unicode NFKC 规范化
2. 去 HTML 标签、URL、@提及
3. 噪声词过滤（哈哈哈/233/666 等正则）
4. 重复标点压缩（`([。！？!?~～，,.])\1+` → `\1`）
5. 空白合并

### 词典预筛（lexicon.py）——核心算法

内置词典：正词 41 个、负词 41 个、程度副词（权重表）、否定词 14 个、负面强化词 8 个（塌房/翻车/暴雷/智商税/割韭菜/逼氪/欺诈/事故，触发直接 -1.2）。

评分算法：

```
对每个命中词：
  前 2 字符窗口匹配程度副词 → degree（极2.5/太2.2/超级2.2/非常2.0/很2.0/十分2.0/特别2.0/相当2.0/比较1.3/挺1.3/蛮1.3/有点0.8/稍微0.8/略0.8）
  前 2 字符匹配否定词 → 极性翻转（×-0.8）
  正词 += 0.5 × degree × (negated?-0.8:1)
  负词 -= 0.5 × degree × (negated?-0.8:1)
score = tanh(|total|/3) 按符号
标签：score>0.15 正面；<-0.15 负面；否则中性
置信度：|score|≥0.15 → min(|score|×2.5, 1)；否则 max(1-|score|×3, 0)
无任何命中 → confidence = min(confidence, 0.2)（交给 LLM）
```

### LLM 分析器（llm_analyzer.py）——三大职责

**配置**：`LLMConfig(api_key, base_url, model)`；默认 `https://api.deepseek.com` + `deepseek-chat`（预设）。未配 Key 自动降级 `MockAnalyzer`（词典）。

**职责 1：情感精分析（analyze_batch）**

- 批量：10 条/请求，最多 4 并发（ThreadPoolExecutor），内存缓存去重
- `_chat` 参数：`temperature=0.2`、`response_format={"type":"json_object"}`、`max_tokens=min(2000, 150+100×n)`、超时 60s；`deepseek-reasoner` 自动省略 temperature/response_format
- 系统提示词要求返回 `{"items":[{"index":0,"sentiment":"positive|negative|neutral","score":-1~1,"confidence":0~1,"keywords":[≤3个]}]}`，按 index 对齐
- 批次失败 → 词典兜底 + 记录 `errors`（结果页展示"LLM 提示"）

**职责 2：叙事/归因（analyze_narrative）**

- 10 条/批并发；`max_tokens=min(1500, 120+60×n)`
- 五框架：conflict/human_interest/attribution/economic/morality；八归因：government/enterprise/individual/system/technology/society/nature/unclear
- **取值清洗**（`_sanitize_narrative_items`）：非法值（如模型把 unclear 误填进 narrative）自动置 None 并记录错误，绝不抛异常（曾因此崩溃，回归测试覆盖）

**职责 3：深度洞察（generate_insights）**

- 输入 12 图的中文统计描述，要求输出 `{"chart_insights":{12个key的解析},"conclusion":"300~500字按五叙事框架的结论"}`，`max_tokens=3500`、超时 120s
- 失败 → 模板洞察兜底

### 编码编排（coder.py）

```
每帖：正文清洗 → 词典预筛 → 维度标签匹配（schema 关键词 contains）
  置信度<0.4 且 LLM 可用 → 标记待 LLM
每评论：同上
→ 待 LLM 文本一次性 analyze_batch（内部并发）
→ [可选] method=="llm" 的文本做叙事/归因
```

要点：`method` 标签反映真实来源（LLM 不可用时即使开关开着也只标 lexicon）；叙事分析只对 LLM 精分析过的文本执行（控制成本）；强度 `intensity = min(max(int(|score|×5)+1,1),5)`。

### jieba 分词（tokenizer.py）

- 环节：编码完成后的**文本统计环节**
- `segment()`：`jieba.lcut` → 过滤单字/纯数字/无中文/停用词（约 200+ 词，含虚词如"看看/确实/越来越"）
- `build_word_freq`：内容词 Top50 → 词云 + 内容高频词
- `build_cooccurrence`：句子窗口 3 词内词对共现，Top30 → 共现网络图

## 十一、洞察与结论生成（insights.py）

### 图表描述（build_descriptors）

把 summary 数字转中文描述，12 个 key：overall/platform/trend/dimensions/heatmap/words/intensity/radar/platform_dim/date_dim/wordcloud/cooccurrence。示例：

- overall："共编码 N 条…正面 x 条（y%）、负面…平均情感分 a，整体倾向…"
- trend：前半段 vs 后半段均分 → 上升/下降/平稳；讨论高峰日；负面峰值日
- platform_dim：每平台负面率最高维度
- date_dim：负面率最高的前 3 个 日期×维度

### 模板洞察（template_insights，兜底）

每图 2~4 句数字驱动解析；结论按五叙事框架给 5 条建议（责任归因优先、冲突化解、人情味 UGC、经济后果评估、道德危机最高优先级）。

### LLM 深度结论（generate_insights）

见 §十 职责 3。LLM 可用时优先，模板兜底。

### HTML 报告（html_report.py + report.html.j2）

12 项可视化 + 每图下方解析文字 + 深度结论。模板结构：header 概览卡 → 警告框 → 情感与分布 → 时间趋势 → 情绪强度 → 维度分析（含热力/雷达/日期×维度）→ 平台×维度 → 高频词+词云 → 共现网络 → 叙事表（可选）→ 概览 → 深度结论 → 方法与数据说明。

图表实现要点：

- 全部 `plotly.graph_objects`，离线嵌入：首图 `include_plotlyjs=True`，其余 False
- 词云：`wordcloud.WordCloud(font_path=msyh.ttc, width=900, height=450, collocations=False, random_state=42)` → base64 data URI 嵌入
- 共现网络：`networkx.spring_layout(seed=42, k=0.6)` 布局，边线+节点散点
- 日期×维度热力：z 为 negative_rate，空数据 None + 空文本
- 雷达：负面率 + 平均分映射（(score+1)/2）双序列

### Word 报告（word_report.py）

章节：标题/生成时间 → 分析概览表 → 情感分布表 → 平台统计表 → 维度表 → **图表与解析**（11 张 kaleido 渲染 PNG + 词云图，每图标题+解析文字）→ 深度结论 → 概览 → 注意事项。

kaleido v1 关键实现：

```python
from kaleido import calc_fig_sync, start_sync_server
start_sync_server(silence_warnings=True)   # 进程内只启动一次
data = calc_fig_sync(fig, opts=dict(format="png", width=850, height=480, scale=1.1))
doc.add_picture(BytesIO(data), width=Inches(6.2))
```

复用同一渲染服务，11 张图约 20 秒（每张新起进程则需 140+ 秒，禁止）。

### 结果 JSON

`bundle.model_dump_json(indent=2)`：plan/summary/report_text/chart_insights/conclusion/warnings/coded_items。

## 十三、进度与异常处理

### 阶段权重（pipeline.py）

collecting 0.0~0.5 → cleaning 0.5~0.6 → coding 0.6~0.9（词典预筛 0.6~0.75、LLM 0.75~0.9，叙事启用时 LLM 0.75~0.825、叙事 0.825~0.9）→ reporting 0.9~1.0。

### 任务清单（progress.py）

6 步：采集/清洗/词典预筛/LLM 精分析/叙事归因/生成报告，每步 state(pending/running/done/skipped/failed) + detail + frac。LLM 未启用 → skipped；无 Key → skipped(未配置 API Key)；连接失败 → failed(已降级词典)。

### 异常处理

| 场景 | 处理 |
|------|------|
| 单渠道失败 | degraded 降级，保留已采数据，继续 |
| Cookie 缺失/过期 | 降级 + warnings 提示"需要 Cookie/更新认证" |
| LLM 连接失败 | ping 自检失败 → 自动换 Mock + 警告 |
| LLM 批次失败/非法值 | 词典兜底 + errors 记录 + 清洗，不中断 |
| 样本不足 | 质量门控：<10/<30/<45/<100 逐级降级提示 |
| 用户取消 | cancel_event（V2 完善为任务队列） |

## 十七、已知限制与路线图

### 已知限制

- 小红书楼中楼依赖 opencli 接口（当前仅返回顶层评论）
- websearch 纯品牌词丢弃率可能仍 >15%（评价后缀+补采已缓解；关键词效果可反馈优化）
- 词典预筛对反讽/网络黑话仍有误差（由 LLM 兜底，阈值 0.8 送 LLM 占比约 70%）
- 抖音渠道未接入（V2 路线图待定优先级）
- 单任务同步执行，关页面即中断（V2 引入后台任务队列）
- Word 图表为静态 PNG（无交互）

1. B站公开 API → WebSearch（360+Bing，含知乎/贴吧/TapTap 子渠道）→ 微博 Cookie（hotflow）→ 知乎（并入 WebSearch）→ 小红书 opencli —— 全部完成（2026-08）
