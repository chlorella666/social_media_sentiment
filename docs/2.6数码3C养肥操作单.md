> [抽样与标注规范 §十五](抽样与标注规范.md) · [2.6提准跑分操作单](2.6提准跑分操作单.md)

## 一、采集（你侧，应用向导）

1. **新建任务**，领域选「数码3C」，品牌建议：**大疆 / 影石 / 联想 / 华为**
   （可加苹果；每品牌 1 个任务，共 2~4 个任务）；
2. **关键词**：在领域自动生成关键词基础上，追加口语评价类词：
   `评价 怎么样 好用吗 值得买吗 吐槽 翻车 真实体验 优缺点`——
   这是养肥的关键，纯参数词只会再采回介绍文；
3. **渠道**（按健康度排序）：
   - B站（公开 API，稳定，评论区体验文本多）——主力；
   - 微博（Cookie 已在侧边栏持久化则优先，体验/吐槽多）；
   - 小红书（登录态可用则适量，反爬严，量少）；
   - WebSearch（当前风控，可用但量少，作补充）；
4. **评论开关**：开启抓评论（真实体验多在评论而非正文）；
5. 规模目标：原始量合计 **≥300~500**（去重后 ≥250），单品牌 ≥80；
6. 任务完成后，把任务目录名（`data/reports/<时间戳>`，共 2~4 个）发我。

## 二、hold-out 切分（我侧，工具已就绪）

命令（示例，由我按实际任务目录执行）：

```bat
python tests/coldstart_annotation.py --holdout-split --from-report data/reports/<ts> --domain digital3c --n 40 --out-dir data/datasets/holdout_digital3c
```

产物：

| 文件 | 内容 |
|---|---|
| `holdout_digital3c_worksheet.xlsx` | hold-out 标注表（约 40 条，渠道/品牌配额 + 时间窗三分桶） |
| `iteration_digital3c_worksheet.xlsx` | 其余样本（后续并入 3C 迭代集） |
| `holdout_split_digital3c_manifest.json` | seed/配额/时间窗/校验结果（**issues 为空才算合格**） |

校验口径：分层占比偏差 >10pp 或时间桶缺失（池内 ≥10 条）→ 切分不合格，我会补采后重切。

## 三、标注（你侧，流程同 2.5）

1. 双 AI 独立标注：workbuddy 主标 + trae 副标（口径沿用
   [2.5数码3C副标口径与试标](2.5数码3C副标口径与试标.md)）；
2. 一致性核对（随机 ≥60 条 + 高歧义 100%）→ 人工抽检校准；
3. 达标线：整条情感一致率 ≥0.8、kappa ≥0.6、维度级 ≥0.75（维度为 A 档参考）。

## 四、定版与冻结（我侧）

```bat
python tests/coldstart_annotation.py --finalize --primary <主标.xlsx> --secondary <副标.xlsx> --out data/datasets/holdout_digital3c.csv --domain digital3c --fixture-out tests/fixtures/holdout_digital3c.csv
python tests/coldstart_annotation.py --freeze-holdout --golden tests/fixtures/holdout_digital3c.csv
```

冻结后：hold-out **只读**（错误不进失败模式、不改规则）；跑分自动计数 ≤2 次；
**首跑 = 建立基线，不构成提升判定**。

## 五、迭代集并入 3C golden（我侧，需你确认口径）

- iteration 标注定版后，与现有 160 条 3C golden **按原文去重**后合并（升 v2）；
- 局限说明：`coded_items` 不含 URL，跨任务去重只能用原文近似（同内容不同平台
  改写可能漏去重，可接受）；
- 3C golden 指纹变化 → 旧基线对比被守卫拦截（预期机制）→ 你侧按
  [跑分操作单](2.6提准跑分操作单.md) 重跑 3C 混合 2 轮，我重冻结基线。

## 六、风险提醒

1. **渠道风控**：WebSearch 当前风控中、微博需 Cookie 持久化——采集前先跑渠道体检，
   失败渠道不阻塞，用可用渠道补量；
2. **养肥 ≠ 切分自动纠偏**：如果新任务仍是介绍文为主，hold-out 也会偏介绍文；
   所以关键词追加口语评价词是关键步骤，采完我会先给你一份"文本类型分布"再切分；
3. **数量不足**：去重后 <200 时建议补采；hold-out 池不足 30 时先不切，等补够。
