### 2026-08-14（领域配方模型决策：主导对象模板 + 叠加维度）

- 用户评审确认（承接 2.4 启动同日）：领域分类不是互斥归属，而是"主导对象模板 + 叠加
  维度"的配方——任何品牌 = 选一个主导模板打底 + 按对象属性叠加维度；混合属性用加维度
  解决，不逼用户二选一（案例：华润万家 = 服务主导 + 实物叠加"商品品质/价格促销"，
  模板用 service，schema 补实物维度）。
- 三条原则：① schema 驱动一切（标注/评测/报告/统计从领域 schema 动态渲染，代码
  零写死）；② 运行时自包含（维度全部物化在领域 JSON，模板只用于创建选型，改模板不
  级联破坏已上线领域）；③ 裁判先行 + A 档收口（每领域独立裁判，样本不足维度不设
  硬门槛）。
- Schema v2 字段（向后兼容，旧文件缺省）：`version`（缺省 1.0，变更触发该领域基线
  重冻结）、`template_id`（content/physical/service，缺省按领域推断只读不改行为）、
  `dimension.origin`（template:* / domain，缺省 domain）。
- 模板库 `app/domains/domain_templates.json` 三套起步（草案，标准维度待 2.5 证据定稿；
  存放于 schema 目录入库受版本管理）：
  content 内容型（数字内容产品）/ physical 实物型（有形商品）/ service 服务型
  （服务过程）；维度数量约束 3~10，超出需评审。
- 冷启动流水线（新领域上线标准流程，2.5 后启用）：2.5 提案（模板建议 + 维度候选
  两件套）→ 人工配方确认 → 小样本裁判（100~200 条双 AI + 人工抽检，维度列动态渲染）
  → 独立基线冻结 + 发布 → 数据养肥迭代（schema v2 重冻结）。成本 ≈ 2~3 天/领域，
  大头为标注人工。
- 与 2.5/2.8 衔接：2.5 定位升级为"领域扩展提案引擎"，输出模板建议 + 维度候选，
  依赖 2.4 schema 机制落地；2.8 维持"自定义维度仅采集关键词、不参与统计"，补升级
  通道（自定义维度 → 提交领域提案 → 2.5 人工确认 → 转正式维度）。
- 决策点四项确认：① 运行时物化 + origin 标签（安全优先）；② 模板库本轮只留字段、
  草案放文档，等 2.5 证据定稿；③ 维度数量 3~10；④ 本轮 2.4 只做最小机制
  （schema 三字段 + 复核表动态列 + 契约测试 + UI 文案 + 文档），模板库/脚手架/
  冷启动流水线归 2.5。

  维度关键词 → 话题词反查 → 整体负面文本），LLM 只解读给定证据、不选材；
  ② 结论区从"五框架必写"改为"发现驱动"（claim + evidence_refs + action），
  五框架降级为归因标签；
  ③ **无 LLM 模式保留方向性提示、不给出强动作建议**（词典精度不足，避免误判
  触发错误行动）；证据标注"词典判定·仅供参考"，并提示升级 LLM 精分析；
  ④ 验收六条（含无 LLM 专属：结论数据驱动 / 无强动作建议 / 负面高时禁写
  "中性/正面为主"）。

## 附录 B：阶段 1 总结——稳定性与工程化的意义（2026-08-10）

> 2026-08-10 | 范围：1.1~1.9 与 1.5~1.7（v0.6.0 → v0.14.0）| 阶段 1 出口达成后归档

**一句话总结**：阶段 1 把"能跑通分析的脚本"升级成了"可以放心交付、可以长期使用、
可以继续演进的产品底座"。

### B.1 解决了四类问题

1. **让用户敢把任务交给它（可靠性）**
   - 关掉浏览器任务照跑（1.1 后台队列 + 常驻 worker）、崩溃可重跑；
   - 历史任务可回看、可一键重跑（1.2），分析不再是"一次性消耗品"；
   - 任何失败都能定位"哪一步、为什么、怎么办"（1.3 结构化日志 + 错误建议），
     小白也能自助排查。
2. **让账号和数据不被玩坏（安全与合规）**
   - 渠道每日限额、风控自动退避、暂停恢复（1.4）——防封号，真实渠道才敢长期用；
   - API Key 迁入 Windows DPAPI、明文文件清除、环境变量退出应用链路（1.5）——
     密钥不落地；
   - 《使用边界》首次启动确认页 + LLM 数据出境明示（1.5）——阶段 4 对外分发的
     合规前置，提前做掉。
3. **让质量有裁判、有门禁（工程化）**
   - 黄金集基线归档 + 一键回归 + 双平台 CI（1.6）——以后每次改动，准确率跌破 1pp
     或任何功能坏了都会自动 FAIL，不再靠"感觉没改坏"；
   - 渠道/领域扩展有 schema 契约检查（1.6）——加新渠道不会悄悄破坏老功能；
   - 磁盘占用可见、旧报告自动归档、超期显式清理、worker 磁盘预检（1.7）——
     长期使用不把磁盘撑爆。
4. **为阶段 2/3/4 铺好路（战略意义）**
   - 阶段 2（分析质量）要反复改词典/提示词 → 没有 1.6 的回归门槛，每次改都提心吊胆；
     没有 1.2 的历史重跑，改进没法对比；
   - 阶段 3（定时监控、告警、对比分析）→ 依赖 1.1 的常驻队列、1.2 的历史数据、
     1.4 的配额风控；
   - 阶段 4（打包分发、隐私专项）→ 1.5 的确认页和 DPAPI、1.7 的数据分类与安全
     排除清单、1.6 的回归都是出口硬门槛的前置；
   - 最终形态"网页版（混合形态）"直接复用这套队列、凭据、契约和回归能力。
