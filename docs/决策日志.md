### 2026-08-10（网页版方向确认，侧线讨论）

- 讨论产品最终形态：用户不下载包、通过网页直接使用。
- 决策：**最终形态 = 网页版（混合形态：本地采集 + 云端分析）**；采集器采用**浏览器扩展**
  （不采用桌面轻代理：会被替换的双份成本 + 安装包信任/杀软/跨平台问题）。
- 目标用户：个人自助 / 小团队 / 品牌方；渠道保留微博/小红书登录态采集（社媒核心），
  公共渠道（B站公开 API / WebSearch / 知乎 / 贴吧）云端直采。
- 多租户：登录 + 每用户独立 SQLite + 管理员密码管理；LLM Key 与登录态均为用户自备，
  LLM Key 云端可选记忆（服务端加密），登录态 Cookie 只存本地扩展、绝不传云。
- 商业化：3 次免费体验（运营方出 LLM）+ 邮箱验证门槛；订阅制（BYOK 基础档 + 运营方 LLM 专业档）；
  定价无初值，采用"成本地板×倍数 + 竞品锚点 + 内测校准"。
- 扩展范围只覆盖微博+小红书；先微博单渠道 MVP，小红书（反爬重）放第二步。
- 抖音复核：维持延后（风控严、水军/机器人占比高，收益不确定）；重开需先做受控预研。
- 产出：[网页版演进路线图.md](网页版演进路线图.md)（决策整合 + 四步执行路线）。

## 附录 B：阶段 1 总结——稳定性与工程化的意义（2026-08-10）

> 2026-08-10 | 范围：1.1~1.9 与 1.5~1.7（v0.6.0 → v0.14.0）| 阶段 1 出口达成后归档

**一句话总结**：阶段 1 把"能跑通分析的脚本"升级成了"可以放心交付、可以长期使用、
可以继续演进的产品底座"。

### B.1 解决了四类问题

1. **让用户敢把任务交给它（可靠性）**
   - 关掉浏览器任务照跑（1.1 后台队列 + 常驻 worker）、崩溃可重跑；
   - 历史任务可回看、可一键重跑（1.2），分析不再是"一次性消耗品"；
   - 任何失败都能定位"哪一步、为什么、怎么办"（1.3 结构化日志 + 错误建议），
     小白也能自助排查。
2. **让账号和数据不被玩坏（安全与合规）**
   - 渠道每日限额、风控自动退避、暂停恢复（1.4）——防封号，真实渠道才敢长期用；
   - API Key 迁入 Windows DPAPI、明文文件清除、环境变量退出应用链路（1.5）——
     密钥不落地；
   - 《使用边界》首次启动确认页 + LLM 数据出境明示（1.5）——阶段 4 对外分发的
     合规前置，提前做掉。
3. **让质量有裁判、有门禁（工程化）**
   - 黄金集基线归档 + 一键回归 + 双平台 CI（1.6）——以后每次改动，准确率跌破 1pp
     或任何功能坏了都会自动 FAIL，不再靠"感觉没改坏"；
   - 渠道/领域扩展有 schema 契约检查（1.6）——加新渠道不会悄悄破坏老功能；
   - 磁盘占用可见、旧报告自动归档、超期显式清理、worker 磁盘预检（1.7）——
     长期使用不把磁盘撑爆。
4. **为阶段 2/3/4 铺好路（战略意义）**
   - 阶段 2（分析质量）要反复改词典/提示词 → 没有 1.6 的回归门槛，每次改都提心吊胆；
     没有 1.2 的历史重跑，改进没法对比；
   - 阶段 3（定时监控、告警、对比分析）→ 依赖 1.1 的常驻队列、1.2 的历史数据、
     1.4 的配额风控；
   - 阶段 4（打包分发、隐私专项）→ 1.5 的确认页和 DPAPI、1.7 的数据分类与安全
     排除清单、1.6 的回归都是出口硬门槛的前置；
   - 最终形态"网页版（混合形态）"直接复用这套队列、凭据、契约和回归能力。
